## 0. 总则

### 0.1 三条基础事实（决定本清单为何必须存在）

1. **CI 有 windows 真机腿，但日志分不清"真跑"与"整包 Skip"**：`scripts/test-windows-quarantine.sh` 在 `QUARANTINE` 空清单分支里的 `exec go test -count=1 ./...` 与 CI 三条腿都不带 `-v`（04 以短语"三条腿都不带 `-v`"多处自认，登记行为 §6.11 表内 **M100**）。因此凡标注"CI windows 腿已绿"的项目，其 Skip 出口项一律按"无读数"处理。
2. **判定逻辑住在无 tag 文件里，Linux 主门禁只证明判据表，不证明 Windows 胶水真读到过正确的字节**（ads / sysguard / realbytes / cloudfile / fscase / recycle_policy 同族分层纪律）。
3. **CI 三条腿都不起 GUI，也不碰真实回收站**：现读 `.github/workflows/ci.yml`，三腿的 step 只有 `go vet` / `go test -race` / `npm` 构建 / `fdd-cli` 冒烟（跨卷冒烟刻意只在 ubuntu 跑），同一文件头注"尚未纳入"里自认两条——"macOS/Linux 真实回收站与 GUI 端到端：需人工或桌面会话""macOS 侧跨卷冒烟：harness 依赖 losetup/mount -o loop，仅 Linux 可用"。⇒ **窗口前置/合并、真实回收站两类格在三腿上都是零读数**，darwin 与 linux 在这一点上跟 windows 处境相同；这就是本文从单腿扩成三腿的全部理由（04 §6.36 五的 ★ 格、P10 末尾的 ★ 注）。
   ★ **"真两卷"不在这条零读数清单里，但它只兑现了一半**（〔2026-09-24 M209 当日现读更正，本条初稿写的是"三腿都不给真两卷"，那是过强口径〕）：ubuntu 腿的 `scripts/smoke-symlink.sh` 真挂 loop + ext4（当日 CI 日志原文 `卷 A dev=2049 ｜ 卷 B dev=1792`，且"① 硬链接跨卷（预期失败）"拿到的是内核报的**真实** `Invalid cross-device link`），七条判据当轮全成立——所以"独立卷"这一形态在 CI 上**有**读数。它没覆盖的是 **LNX-2 要的那一段**：回收站复制腿（`copy + .trashinfo + 删源`）。那一腿在 Go 用例里靠 `forceCrossVolumeRename` **注入** EXDEV（`move_crossvolume_identity_test.go`），CI 从没在真卷上跑过。⇒ LNX-2 照旧要现场环境，只是**不必再另找第二块物理盘**：同一台 ubuntu 机器上把 `XDG_DATA_HOME` 指到那个 loop 卷即可复现（本格已按此改写）。

### 0.3 环境要求（分腿）

#### 0.3-W · Windows（P0~P10 用）

- **主机**：Win10 1607+ 或 Win11（longPathAware / 开发者模式 / UAC 都依赖版本）；建议 Win11。
- **权限**：同一台机器上既能以**管理员**跑一次，也能以**普通账户（开发者模式开/关两态）**跑（§6.5 E 组四环境）。
- **卷**：NTFS 系统盘 + 至少一个第二物理卷（跨卷腿）+ 一个 **exFAT 或 FAT32 U 盘**（保留名夹具、`index==0` 卷、`CreateHardLinkW` 拒绝路径都靠它）+ 可选 SMB/网络卷、ReFS、BitLocker 卷。
- **注册表可写**：`HKCU\...\Explorer\BitBucket`（NukeOnDelete 场景）、`HKLM\...\FileSystem\LongPathsEnabled`（长路径两态）。
- **云客户端**：一个已配置 OneDrive 账户（占位文件场景 M31）。
- **杀软现实性**：至少一轮在**带第三方 AV / Defender 实时防护开启**的机器上跑（04 §6.6.3 拒绝原因表点名的"北信源防病毒接管/清理 `$Recycle.Bin`"、§6.6.4 点名的"目标环境（本机 Win11 + 北信源）`LongPathsEnabled` 取值未确认"两类干扰面：句柄占用、Minifilter 卷重定向、回收站目录接管）。
- **产物**：用 `wails build -platform windows/amd64` 或 build.yml 产出的 zip 裸 exe（未签名）；**不要**用 `GOOS=windows go test` 交叉跑代替 GUI 验收。
- **读数留档**：每项记录 OS 版本 / 卷文件系统 / 是否提权 / 开发者模式态 / AV 状态，按对应 M 编号回填 04。

#### 0.3-M · macOS（`## MAC` 用，2026-09-24 M209 新增）

- **主机**：Apple Silicon 或 Intel 的**真实 macOS 桌面**，且执行者处在**GUI 登录会话**里（SSH 进去的会话没有窗口服务器，MAC-1/MAC-2 直接不成立——那不是"未通过"，是"环境不满足"，按 SKIP 记）。
- **版本留档**：macOS 版本 + 系统卷/数据卷是否分离（`/System/Volumes/Data` 形态影响 MAC-3 与 LNX-1 那类跨卷对照），以及是否 FileVault。
- **iCloud**：MAC-4 需要**已配置 iCloud Drive 且能生成占位文件**的账户，并且**用户在场同意下载配额**——这条前提是 M31 登记时就写死的，不是清单自己新加的（原文见 04 的 M31 行"可兑现形状"）。
- **终端可见**：MAC-2 的**唯一**痕迹打在标准输出上，所以那一格必须从终端启动裸可执行文件（`FileDedup.app/Contents/MacOS/FileDedup`），从 Finder 双击启动会看不到。
- **访达自动化授权**（2026-09-26 第六轮审查新增）：回收站那一腿的动力来自 macOS「自动化」授权——
  **系统设置 → 隐私与安全性 → 自动化 → 访达（Finder）下的 FileDedup** 必须勾上，否则 Finder 一律回
  `-10004 权限违例`，表现为"操作走完了流程、但每一项都失败"，**文件一个都没被搬走**（判据与用户话术见 09 §6.3.0 / 10 §2.7.1）。
  这一格的要求是双向的：① 上机前先确认已授权；② 万一测出来"-10004"，先去开关那里补授权再重跑，
  **不得**据此判定回收站实现有问题。自动化脚本/CI runner 常处于从未授权的状态，那种环境的表现就是"全部失败"，
  属**环境不满足**，按 SKIP + 原因记（同本段首条 SSH 会话那一条口径）。
- **产物**：`wails build -platform darwin/universal` 的 `.app`；不要用 `GOOS=darwin go test` 代替 GUI 验收（同 0.3-W 那条纪律）。

#### 0.3-L · Linux（`## LNX` 用，2026-09-24 M209 新增）

- **主机**：一台真实 Linux 桌面/会话。LNX-5 需要**两态各跑一次**：有 D-Bus 会话总线、没有会话总线。
- **卷**：至少两个**不同文件系统**的挂载点（第二块盘或 `losetup -f --show` + `mkfs` 的 loop 卷即可），LNX-2/LNX-4 靠它。★ 现读：CI 的 ubuntu 腿就是这一形态（`smoke-symlink.sh` 真挂 loop + ext4 并拿到真 EXDEV，见 §0.1 第 3 条那条更正）——所以 LNX-2 的"两卷"半边可以就地复用，缺的只是把 `XDG_DATA_HOME` 指过去那一步。
- **网络文件系统**：LNX-4 需要挂得上 sshfs 或 NFS 其中之一；**挂不上就按 SKIP + 原因记**，不得用本地卷的读数替代（该格测的就是"该卷不跟踪块数"这一环境形态）。
- **GNU coreutils**：LNX-6 需要 `timeout` 命令在位（busybox 版不算——判据点是 rc 与 `--kill-after` 语义）。
- **桌面环境**：LNX-2 的"回收站看得见"要一个遵循 freedesktop Trash 规范的 DE（GNOME Files / Dolphin 任一）。
- **产物**：`wails build -platform linux/amd64`，或直接 `fdd-cli`（无 GUI 的那几格 CLI 就够，LNX-5 必须有 GUI）。

## P0 · 回收站防线（H6 / §6.6.3 E 组）——最高优先级

失败模式是**静默永久删除**，且三层防线（预检 fail-open → 事后复核可 Skip → executor 严格回退只有注入测试）**没有任何一层有真机读数**（域 A/T-5）。

| # | 场景 | 操作方式 | 结果验证（判据） |
|---|---|---|---|
| W1-1 | 正常入站 | 对 NTFS 卷上一批小文件（含中文名、含 >1000 项混合列表）执行"移入回收站" | ① 源路径消失；② 文件出现在**该卷** `$Recycle.Bin`（系统回收站可见、可"还原"回原位）；③ 应用历史里 kind=trash、`DestPath` 恒空（结构性缺失，记录读数即可）、徽标/title 走 `undoableFor(trash,windows)`＝不可应用内回撤；④ 三判据事后复核（源不在 + 该卷条目增量==预期 + 入站时间基线）全部通过，无「可能已被直接删除，请立即到回收站核实」误报（`executor.go` trash 回退分支文案，见 W1-3 勘误） |
| W1-2 | 超配额拒绝 | 把测试卷回收站属性容量设为 **1MB**，对单个 >1MB 文件执行移入回收站 | 见**含容量数字的拒绝提示**（`capacityReason`），文件仍在原位；不得出现"报成功但文件消失" |
| W1-3 | 批量部分超限 | 混合"能进 / 不能进"的多文件一批执行 | **整批拒绝**（`internal/ops/trash_windows.go` 的 `defaultTrash` 预检注释原话"任一不满足即**整批拒绝**"，判据函数 `recyclableReason`/`recycleBinCapacityReason`）；若走 executor 逐个回退，被 Shell 静默丢弃的条目必须记 Failed（`Execute` 的 trash 回退分支，文案「可能已被直接删除，请立即到回收站核实」——〔2026-09-24 M205 勘误〕此清单旧版把该文案写作"疑似已被直接删除"，与码内字面有别，grep 时以 `executor.go` 现文为准），而非 Skipped。此语义 Windows 独有、至今零真机观测 |

| W1-7 | SHQueryRecycleBinW / 卷 GUID | 让带 `-v` 的 windows 腿（或本机 `go test ./internal/ops -run Recycle -v`，需 GTest 环境）真跑 `trash_windows_recycle_test.go` | 四组可 Skip 用例（`TestVolumeGUIDShape` / `TestRecycleBinCapBytesSystemDrive` / `TestQueryRecycleBinSystemDrive` / Nuke 三态两条：`TestWinNukeStatusOfDistinguishesAbsentFromUnreadable` + `TestRecycleBinVolumeNukeSystemDrive`）**逐条报 PASS 而非 SKIP**；`shQueryRBInfoSize==20` 布局钉在真 Shell 上语义正确 |

| W1-11 | 回收站反查的两格：`$R` 实体不验存在 ＋ 进站窗口带 2 分钟 slack（**M332 / OPS-47，本轮登记不修**） | Windows 真机、NTFS 卷、普通（非提权）账户。★ 挂在本组是因为判据本体在无 tag 的反查逻辑里，但**能不能读到只有 Windows 说了算**——darwin 连 `$Recycle.Bin` 下的 SID 子目录都枚举不出来。**臂①（`$R` 不验存在）**：把一批小文件移入回收站，然后在界面点"打开该项 / 回撤"**之前**，用资源管理器把对应的 `$R…` 实体改名或搬走、`$I…` 元数据留在原地 ⇒ 再点一次。**臂②（2 分钟 slack）**：对路径 P 上的文件 A 执行移入回收站，随即（<2 min）在**同一个原路径 P** 上重建同名新对象 B（内容故意不同）⇒ 再跑一次扫描，读反查表把 P 配到了哪个落点。 | ① 臂① 判据：`$R` 实体不在场时反查**不得**报"该文件在回收站里"——应交回空表，让执行器那条"未证实进站／该卷复核不可用"的口径原样生效；若台账先声称有落点、点了才失败 ⇒ **FAIL**（M279 修的是假警报，本格防它长成**假确认**）。② 臂② 判据：B **不得**被配进 A 的旧 `$R`；区分手段是 `$I` 头部删除时间与条目 mtime（本仓注释原话：真机读数里两者逐秒一致，slack 挡的是时钟粒度与 FAT 的 2 秒步进）⇒ 若真读到"B 顶替 A"，把两文件时间戳的原始差值抄进账，修法（收窄 slack 还是加一次实体校验）由那一格读数决定。③ ★ 只读纪律：`$Recycle.Bin` 是 sysguard 列出的"整仓任何写路径都不得触碰"目录，破坏动作一律由 Shell／资源管理器侧**手工**做，探针自己**一个字节都不许往那目录写**。④ 造不出（无第二账户、SID 子目录列不出、`$R` 侧改不动）⇒ 记 SKIP + 原因，**不得**用 XDG 或 macOS 的对格顶替（那两条腿是另一套实体布局，测不到这两格）。 |

## P1 · 长路径链路（T04 / §3.5#4 / §6.6.4 / M33）

manifest 的 `ws2:longPathAware` 元素已声明（`build/windows/wails.exe.manifest`）但**注册表前提、双条件生效、进程缓存**全部未复测。

| # | 场景 | 操作方式 | 结果验证 |
|---|---|---|---|
| W2-1 | 长路径扫描/移动/回撤 | 构造 >260 字符深度的重复文件若干，`LongPathsEnabled=1` 态下扫描→移入回收站→（非 trash 类）回撤 | 扫描可见、操作不报 `ERROR_PATH_NOT_FOUND`；回撤成功 |
