本目录分**三层**，性质不同、维护规则不同。找错层会得到过期结论，所以先选层再读。

## 二、三层结构与维护规则

### 活文档（内容随实现更新）

- `09-用户手册.md` — 面向使用者。**版本号声明位之一**（`scripts/check-version-sync.sh` 校验
  「适用版本：」，共 **6 个取值位 / 5 个文件**必须对齐——`frontend/package-lock.json`
  贡献 2 个取值位：顶层 `version` 与 `packages[""].version`）。
  ★ 同一脚本自 M210（2026-09-24）起另有 **B 组活文档计数锚**：`04` 的 §3.2 逐包与合计与平台三格、
  §4.1 前端、§4.3、本文件的勘误表条数、§7 的包数与门禁脚本名单，都与代码现读真值逐格比对，
  **锚点读不到即判红**（不是跳过）。⇒ 改这些表时若忘了同步数字，本地第 12 行门禁与 CI 会一起红。
- `04-开发与测试计划.md` — 面向工程。**V2.0 起是现状与质量门禁文档，不再是计划**：
  §1 交付总览、§2 实现面现状、§3 测试体系、§4 CI 现状、§5 门禁约束力、§6 开放项、附录 A 发布清单。
  文件名与 §3.5/§3.6/§4/附录 A 的编号保持不变，因为它们被 `README.md`（§3.5、附录 A）、
  01 §12.1（§3.6）、`internal/ops/ops_test.go:3`（§3.6）、`ci.yml:1`（§4）按号引用。

- `05-真机实测清单.md` — **执行清单，不是事实源**：它只写"上真机要测哪一格、怎么判、
  记什么读数"，判据与来源编号全部指向 04（M7 ⊃ §3.5 / §6.5 / §6.6.3 / §6.6.4 / §6.9.8 / §6.11）。
  三腿分段：P0~P10 是 W 腿（`W*-*`），`## MAC` 是 darwin 腿，`## LNX` 是 linux 腿（2026-09-24 M209 扩）。
  测出来的结论**回填 04**，本文不承载"现在的行为是什么"——所以下面那条"只写进这两份"的规矩不因它而放宽。

- `10-用户使用手册.md` — **09 的用户向派生本，不是第二个事实源**：三段结构（软件说明 / 使用方法 /
  注意事项与排错），删除源码坐标、内部包/函数名、登记号与划账引用，但**行为判据照 09 一字不放松转写**。
  刻意**不带版本号声明位**（版本随 09，避免制造第 7 个无人校验的声明位）；改功能时先同步 09，
  再检查本文对应段落是否需要转写，两文出入以 09 为准。

> 任何"现在的行为是什么"的结论只写进这两份。写进第三份（下面的冻结档案）就是制造第二个事实源。

### 勘误表条数怎么数（2026-09-21 定口径）

上表的 18 / 20 / 12 指**表体数据行**，**不含**表头行与 `|---|` 分隔行。口径不写死的话这一格每次重数都会漂，
所以把命令本身放这里（用字符类 `[|]` 而非 `\|`：后者在 macOS 自带 awk 里解释成"字面反斜杠 + 空交替"，直接语法报错）：

```bash
for f in docs/01-*.md docs/02-*.md docs/03-*.md; do
	printf '%s ' "$f"
	awk '/^> *[|][[:space:]]*-{3}/{t=1;next} t&&/^> *[|]/{n++;next} t{exit} END{print n+0}' "$f"
done
```

2026-09-21 实测输出 `18` / `19` / `12`。

## 四、给改文档的人

1. 改功能 → 同步 `09`（必需，`check-version-sync.sh` 会查版本号）+ `04`（若影响交付状态/门禁/开放项）
   + `10`（若影响用户向的行为判据或操作流程——只转写 `09` 的结论，不在 `10` 里立新口径）。
2. 在 `01`–`03` 读到与代码不符 → 页首勘误表补一行，别改正文。
3. 写了一份日期化审查/审核报告 → 归档前直接并入 `archive/` 对应编年史，不要在 `docs/` 根留下第 12 份散档。
4. `docs/superpowers/` 是 superpowers 工作流产物（计划 + 设计成对），保留原位仅供追溯，
   顶部已标注它与现行实现的偏差；新工作可以直接看 `04` §6。
