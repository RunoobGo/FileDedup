## 二、判据：什么叫"过时"，什么不算

**要动（三处）**：

- **P-1** `docs/04:9329` 那一格把 `?? build/m7scratch/`（13 项 / 76K）当**工作树状态**在陈述。本批 一·3 的动作
  已经在本机否证了它 —— 不改原句（裁-4 禁改历史正文），在《追记》节尾**加一条 2026-10-03 日期化方括号追记**：
  本机该目录已按用户裁定删除、备份在 `/tmp/<时间戳>`（**非长期留存**，重启即失）、"常驻脏项 ⇒ `git add` 一律点名"
  那条防线在本机盘面**已无脏项可挡，但纪律照旧有效**（别的机器/新克隆仍可能产出）。
- **P-2** `docs/05:339` 那句"四个取证通道本体**保留**在 `build/m7scratch/`"是**跨机器**读法：在本机（darwin）
  这四个文件从未在此目录、而本批又把该目录清了。加同一家族的日期化方括号，写明**本机不在 ＋ Windows 真机
  盘面本批未取数 ⇒ 该格不销、口径不改**。（★ 若把它写成"已消失/已失效"就是假账：那一腿根本没读。）
- **P-3** `internal/` 那 4 处注释指针：三处句式是"同批落盘 / 输出留存 `build/m7scratch/…`"，其中
  `recycle_index_test.go:19` 指的 `b9/probe_rb_acl_hex.txt`、`fsid_windows_test.go:69/120` 指的
  `m306_ctime_rename_readings.txt` **在本批删除之前就已不在**（P2-9 当时的原话是"只在这台开发机上成立"）。
  这四条注释的**读数全部写在注释自己身上**（`+514200 ns`、"未推进 4/8"、`$I…len=122` HEX 串、"3 条带 stage / 3 条缺省"），
  所以指针死了不影响判据可核 —— 与裁-4 的立论一致。⇒ 做法是**注释内加一枚短括号**（沿用 `fsid_windows_test.go:112`
  已有的 `〔2026-09-27 M271 更正〕` 形状）标明"留存目录 2026-10-03 已清理，读数以本行为准"，**原句一字不删**。

**不动（三处，各自给理由）**：

- `docs/04` 那 68 行历史划账句 —— 裁-4 明文"不逐条改写、原文一字不删"，一条总追记已覆盖；本批 P-1 只是给那条追记**续新盘面**。
- `specs/` 那 9 行 —— 是当时批次的取证记录（含 audit9 报告 P2-9 自己描述 `?? build/m7scratch/` 的那几行），
  改它等于伪造历史；P2-9 的正文本来就在陈述"它未入库"，**不需要**为今天的盘面重写。
- `.gitignore` —— 收录 `build/m7scratch/` 能把"常驻脏项"根治，但那是**第三件事**：用户本轮逐条给的授权是
  prune 与删除两项（选项里"加 .gitignore"被明确未选）。⇒ 本批**登记不碰**，要做得另请。

★ **为什么不占号**：本批零缺陷 ——（A）三处都是"话与盘对不对得上"，不是行为；(B) 门禁不会因为注释文字而改变判据；
(C) 唯一的真状态变化（目录消失）是用户已裁的动作本身，不是仓库缺陷。与 §6.76 七·3 同一纪律第九次应用。

## 四、边界

1. **本机 ≠ Windows 真机**：本批所有盘面读数是 darwin（macOS 27.0 / arm64）这台。凡是"留存目录现在还在不在"的
   跨机结论，只准写"本机不在"，Windows 腿一律标"未取数"。
2. **备份不是归档**：`/tmp/m7scratch-pre-delete-20261003-104751`（14 文件，md5 与原件全等）在 `/tmp`，
   重启即失；这不是把死资产换了个地方存 —— 用户要的是干净，备份只买本批这一张回程票。
3. **手册双回写条款不适用**：`docs/09`／`docs/10` 的"功能变更须双回写"针对**用户可见行为**；本批零功能变更 ⇒ 不动。
4. **`git add` 一律点名**：本批改动含 Go 文件，提交时照旧点名目标文件，绝不 `-A`（§6.48~§6.52 那几批立的机制，
   本机现在少了 `build/m7scratch/` 这一项脏源，但 `scripts/*.sh` 的 755→644 fileMode 噪音是否还在**要现读**，见 五·3）。
5. **CI**：三笔提交按收口纪律推送后各盯一次 run，划账笔推送后**必须再盯一次**（§6.75/§6.77 两次都是划账笔才撞红）。
