## 2. 逐项设计（落笔前的形状）

### 2.1 D1-1 —— `npm ci` 硬失败（`build.yml:119`）

```yaml
          npm ci
          npm run build
```
注释要点：锁文件已跟踪 ⇒ `else npm install` 不可达；不可达的兜底只在"锁被误删/与
package.json 不同步"时把**未测过的最新依赖树**送进发布产物，`npm ci` 让这两种情况当场红。
口径对齐 ci.yml 三腿（`:77`/`:210`/`:269` 全是裸 `npm ci`）⇒ 改后两份工作流对锁文件的态度一致。

### 2.2 D1-2 —— 发布腿 `go test` 补 `-race`（`build.yml:158`）

```yaml
        run: go test -race -count=1 ./...
```
- 该步骤本就有 `if: matrix.platform != 'windows'`（`:157`）⇒ 只覆盖 linux/darwin 三腿；
  `-race` 需要 cgo 工具链：linux 腿 `:105` 已装 `build-essential`，macOS 腿有 Xcode CLT ⇒ 前提成立。
  windows 腿走 `test-windows-quarantine.sh`（`:165`），**本轮不给它加 `-race`**（mingw 不在依赖清单里）。
- `-race` 会拉长发布腿时长（作业级 `timeout-minutes: 40`）。真时长只有 tag/dispatch 跑才拿得到 ⇒
  **这一格记"代码已改、未兑现"**：若将来超时是红在 timeout（可见），不会被读成绿。

### 2.3 D1-3 —— release job 加并发闸

```yaml
    concurrency:
      group: release-${{ github.ref }}
      cancel-in-progress: false
```
- 为什么挂 job 级而不是 workflow 级：本流水线只有 `release` 腿有对外副作用；
  workflow 级 `cancel-in-progress: true` 会把正在跑的**四腿出包**一起取消，比双发更坏。
- `cancel-in-progress: false` 的取向：同 ref 并发时后来者排队而不是打断先来者（R4-6 要防的
  是"双 tag 并发覆盖同一个 Release"）。
- 形状与 ci.yml 的 workflow 级 `concurrency`（`:31-33`）不冲突（不同文件、不同粒度）。

### 2.4 D3 —— rc=2 一律判红（`ci.yml:151-177` 的 `2)` 分支）

```bash
            2) msg_base="跨卷软链接冒烟以 rc=2 收尾（runner 无法挂载独立文件系统）"
               if grep -q '^SKIP' /tmp/smoke-symlink.log; then
                 msg="${msg_base}——脚本自己认领为跳过，该防线本轮未执行"
               else
                 msg="${msg_base}——且输出里没有以 SKIP 开头的自证行 ⇒ 按真失败处理（M133）"
               fi
               echo "::error::$msg"
               { STEP_SUMMARY 两条成因都写 } >>"$GITHUB_STEP_SUMMARY"
               exit 1 ;;
```
- 保持 M133 的双条件判据**在位**，只是把它的后果统一成 `exit 1`；两成因分开写清，
  这样红的时候人一眼能分"环境退化"与"脚本自己崩在 rc=2 上"。
- 计划里那句"ubuntu 先自证 loop/tmpfs 可用性"不另建探针：`smoke-symlink.sh` 自己
  已经按"loop+ext4 → tmpfs → skip(2)"降级（`:26` 起的注释），它的 rc=2 + 行首 SKIP
  就是那一次自证的读数。**再造一个前置探测等于两份实现同一判据**（M142 那族的教训），
  所以只把它的话说清：环境不可用 ⇒ 红；环境可用而脚本仍 rc=2 ⇒ 红。
- 注释同步改口（`:127-138` 那段"仍不阻断"），并写明这是 D3 推翻旧定性。

### 2.5 M331 —— CI 腿补 `-v` 并把 SKIP 清册打成硬读数

新增 `scripts/ci-go-test.sh`（为什么用脚本而不是在 YAML 里铺四遍管道：`go test -v` 后
接管道会让步骤 rc 变成管道末端命令的 rc，必须显式取 `PIPESTATUS[0]`；四遍铺容易写歪，
且这一格需要能本机跑负控制）：

```bash
set -uo pipefail
LOG="${CI_GO_TEST_LOG:-/tmp/ci-go-test.log}"
rc=0; go test -v "$@" >"$LOG" 2>&1 || rc=$?
sed -E '/^=== RUN/d; /^--- PASS/d; /^    --- PASS/d; /^    === RUN/d' "$LOG"
skip_top=$(grep -c '^--- SKIP' "$LOG" || true)
skip_sub=$(grep -c '^    --- SKIP' "$LOG" || true)
echo "M331_SKIP top=${skip_top} sub=${skip_sub} total=$((skip_top + skip_sub))"
[ "$skip_top" -eq 0 ] || grep '^--- SKIP' "$LOG" | sed -E 's/ \([0-9.]+s\)$//'
printf 'M331_RAW_LOG %s\n' "$LOG"
exit "$rc"
```

- **显示口径**：把 `=== RUN` / `--- PASS`（顶层与子测试）删掉，其余原样进日志。
  为什么这样切而不是整份 `-v` 直铺：`-v` 全量输出在 22 包 × `count=2` 量级上是数万行，
  会把"哪一步真红"淹掉；`fail` 详情行（`    file_test.go:NN: …`）与 `--- FAIL`/`ok`/`FAIL`
  都不带 PASS 形状，不受这次裁剪影响 ⇒ 可排查性不减。
- **rc 取 go 的**：`|| rc=$?` 直接拿 `go test` 自己的码，中间不过管道 ⇒ 结构上不可能取到
  `sed`/`grep` 的码（这条比 `PIPESTATUS` 更硬，且 `bash -u` 下不依赖 pipefail 语义）。
- **SKIP 判色**：只打清册不判红。理由沿用 M318 已经立过的口径——本仓确有合法的
  环境性 skip 先例（`test-windows-quarantine.sh:36-46` 记的 Windows 符号链接那一族、
  `ci.yml:213-214` 的隔离说明），一刀切判红会把门禁训练成"大家都忽略的那一行"。
  **M331 要修的是"读不出来"，不是"不许跳过"**。
- 调用点：`ci.yml` 的 check 腿两步（`-race -count=2 ./...`、`-race -count=4 .`）、
  macos 腿同两步、windows 腿走 `scripts/test-windows-quarantine.sh`——把该脚本末尾两处
  `exec go test …` 改走 `ci-go-test.sh`（保留 `-skip` 锚定与 `exec` 语义）。
  `-v` 由脚本自己加 ⇒ YAML 里的命令行不再重复这个参数。
- 本机 harness **不用**这个脚本（行 6 已有自己的 `-v` 与计数，改它等于动本地口径，
  而本地口径这轮没被点名）。
