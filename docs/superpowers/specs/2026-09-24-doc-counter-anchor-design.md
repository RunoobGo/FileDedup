# 设计段：活文档计数取值位的机器锚（M210 的最小修法）

日期：2026-09-24　承接：**M210**（登记于 04 开放项表，划账见 04 §6.38）　上一批：文档对齐批（`ded279c`）
用户指令："执行"（对 §6.38 末条待裁定的 M210 最小修法点头）

## 0. 本批要拦的是什么

M210 登记的原话是：§3.2 的计数层**每批必漂**，而 M108 给的修法（"逐包相加必须等于全仓 grep"）
只是文档级自约束。本批取证到的关键事实是那条自约束**在错值上照样成立**：

```
792 → 837 那一漂里，合计格与 23 个逐包格是被人一起抄成旧值的，
"837 = 837" 这种式子只证明表内自洽，证明不了表内那个 837 就是代码里的 837。
```

⇒ 缺的不是一条更严的口径文字，是一条**把文档里的数字和代码真值塞进同一次比较**的判据：
文档值 ≠ 现读真值 ⇒ 门禁红。本批就做这一条，不做别的。

产品码零改动、测试零改动、断言一字不减。改动面只有三处：`scripts/check-version-sync.sh`
（加判据）、两份 README 与 04 里"这个脚本查什么"的自述（同步措辞）、04 §6.39 划账。
**`.github/workflows/` 一字不碰**（D1/D3 那条"等我手动改完再说，别动"的边界）。

## 1. 锚点住哪儿：三条路的实际取舍

B1 是本批的主锚：M210 的漂移**逐包格比合计格更容易旧**（合计格每批被人抄，逐包格只有一行人手抄 23 个数）。
只锚合计拦不住它，所以逐包 23 行 × 2 值一并进判据。

实施后的自报读数（脚本末行输出，2026-09-24）：**9 个锚点 / 61 格比对**，其中 §3.2 逐包 **23 行 × 2 值**。
锚点数比组数多是 B3 一格一锚（三个平台三锚）。B1 另含一条"包集合双向对齐"：表里列的包 ≡
目录里有 `*_test.go` 的包，**漏一行或多一行都红**——这一条比"逐包相加 ≡ 合计"更硬，
它拦的是"新增了包却忘了进表"（合计格会被抄，表行数不会自己长）。

## 3. 判据纪律（怎么写才不产假绿）

1. **锚点读不到即红**，不跳过。每个锚要求恰好 1 次命中：0 次＝锚点被改写或格式变了（这正是需要人来改脚本的信号），
   >1 次＝锚点歧义、比对的是哪一格说不清。两种都按 A 组同一句话处理：「请同步更新本脚本」。
2. **真值通道空读数即红**。B3 三平台任一为 0、B1 逐包行数为 0、B6 任一份为 0 ⇒ 判红，
   理由是"加载失败"与"确实没有"必须可分辨。
3. **`go list` 一律带 `-e`，这是本批唯一需要单独解释的取舍**：CI 的 `check` job 里
   版本号那一步在 `ci.yml:72`，前端构建在 `:90`，而那一步跑 `go list ./...` 时仓库里**还没有 `frontend/dist`**，
   根包 `main.go:21` 的 `//go:embed frontend/dist` 会让整条加载红在
   `pattern frontend/dist: no matching files found`（本批用最小复现实测：无 dist 时 `go list ./...` 与
   `go list -f … ./...` 均 rc=1 且**不输出任何文件**；补一个空 `frontend/dist/index.html` 后 rc=0）。
   ⇒ 不带 `-e` 就是"本地绿、CI 红"的假红。带 `-e` 后若加载真的坏了，`TestGoFiles` 会读空 ⇒ 落到纪律 2 的"空读数即红"，
   所以 `-e` 关掉的是**报错文本**，关不掉**判据**。B1 那条通道是纯 `find`+`grep`，完全不依赖 go，两路互为对照。
4. **不新增 run-gates 行、不加 env 开关、不对任何一条比较用 `|| true`**。`set -euo pipefail` 已在，
   所有取数都写成 `x=$(… )` 后判空，不让命令替换的 rc 漏出来变成"脚本中途崩"。
5. **M134 静态防回归**：本文件里凡是变量后面紧跟全角字符（`（`、`）`、`⇒`）的，一律写 `${VAR}` 带花括号，
   否则 `smoke-symlink-assert.sh` E 组会把这一行判红（bash 3.2 会把全角首字节读进变量名）。
6. 输出与 A 组同形：先逐行打印 `取值位 / 文档值 / 真值`，红行走 `fail()`（末尾 `exit 1`），
   全绿才打 `✓`。判据总条数在末行自报，方便划账直接抄。

## 4. 显式不覆盖的（留白写出来，免得下轮当成"锚点已全"）

- §3.2"说明"列与表下追记里的**历史数字**（`272 → 282`、第十一次核对的 792 那类）。那些是当时证词，本就该不等于现值，锚它们＝逼人选"删历史或改历史"，都不许。
- 平台三格"来源"列长句里的 `188 / 190 / 186 个测试文件`（同一格内 prose 与真值同行，正则会和文字打架；B3 只锚数值格本身）。
- 04 §6.x 全部划账正文、`docs/archive/`、`docs/superpowers/`（历史层，只追加不改写）。
- harness 的 `rows=15` 这一格：锚它要数 `run-gates.sh` 里的 `note` 调用，形状脆，且属"文档 vs 脚本自述"而非"文档 vs 代码真值"。
- `docs/09`、`docs/10`、根 README 的叙述性数字（用户手册，M150 之后刻意不背源码计数）。
- 平台三格与 B1 之间的**跨格自洽式**（`837 − 35 − 17 = 785` 那类四象限推导）：锚三格真值后它自动成立，不必单独写。

## 5. 怎么证明它真的会红（本批的验收不是"它现在是绿的"）

一个新判据如果只演示"现在通过"，等于没演示。四格各扰一次，每次跑一次取 rc 与红行原文，然后复原：

| 扰动 | 期望 |
|---|---|
| B2 合计格 `837 → 836` | 红，报文档值 836 / 真值 837 |
| B3 `linux 785 → 784` | 红 |
| B6 勘误表 `20 → 19`（改回 M210 之前的旧值） | 红 |
| B4 把 `= 合计 141 项` 改成 `= 共 141 项`（锚点被改写、命中 0 次） | 红，且红的是"锚点没读到"而不是"数字不等" |

四张红证跑完立刻 `git checkout -- docs` 复原，再跑一次取全绿；红绿两侧读数都抄进 04 §6.39。
