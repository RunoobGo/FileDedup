# 一、软件说明

## 1.1 这是一款什么软件

FileDedup 是一款**按内容识别重复文件**的桌面工具，支持 macOS、Windows、Linux。

它回答一个问题：**这台机器上，哪些文件的内容是完全一样的？删掉多余的那几份能腾出多少空间？**
并给出一套从"看见"到"动手"的完整流程：扫描 → 核对结果 → 选定留谁、动谁 → 执行清理 → 需要时回撤。

三条基本立场：

- **内容级判定**：只有完整内容逐字节一致的文件才会被分到一组。文件名相似但内容不同的一律不报；
- **动手前必校验**：任何清理动作执行前都会重新核对文件内容，扫描之后被改动过的文件会被拒绝操作；
- **默认可回滚**：默认走系统回收站，永久删除需要显式二次确认；清理动手前先记"写前账本"，
  多数操作可以在应用内逐项撤销（**Windows 回收站与永久删除不能应用内回撤**，见 §1.5）。

## 1.2 它怎么判定"重复"

软件用一个逐级收紧的筛选漏斗，每一级都只淘汰"内容不可能相同"的文件，把读盘量压到最低：

1. **先比大小**：大小不同的文件内容必然不同，这一步完全不读文件内容，就能排除绝大多数文件；
2. **再抽几个点采样比对**：对剩下的候选，各读取开头、中间、后段、结尾附近共 4 个片段
  （每段 64 KB）计算"抽样指纹"。指纹不同的直接淘汰——两个文件恰好在大小和这四个分散位置
   全都撞车的概率可以忽略；
3. **再算全量哈希**：抽样指纹相同的文件，才整份读完整内容算一个 256 位"内容指纹"
  （BLAKE3 哈希）。这种指纹在工程上不可能撞车——**指纹相同即认定内容相同**；
4. **（可选）逐字节确认**：对"绝不允许任何理论风险"的场景（如备份核对），可开启 paranoid
   模式，让组内每个文件与代表文件做真正的逐字节比对后才定组。代价是结果阶段多读一趟盘。

两点常见疑问：

- **为什么不会漏报**：内容完全相同的文件，大小、采样、全量哈希每一级都必然一致，任何一级都不可能把它们分开；
- **为什么不会误报**：反过来说，只要内容有任何一个字节不同，大小或采样或全量哈希就会暴露它。
  另外，"改了一部分、首尾没动"的篡改能被中段采样识别，这是复用历史结果仍然可信的前提（见 §1.6）。

## 1.3 哪些文件一定不会被报成重复

以下文件在扫描阶段就被跳过，不会进入结果（除非特别说明）：

| 被跳过的对象 | 原因 | 能否关闭 |
|---|---|---|
| 符号链接 | 不跟随链接，避免环路与重复计数 | 不可 |
| 0 字节文件 | 空文件无内容语义 | 不可 |
| 硬链接的多个名字 | 同一份物理数据的不同名字，只计一次，"可释放空间"不含虚数 | 不可 |
| 应用自己的过程残留（名字以 `.fdd-tmp` / `.fdd-old` 等结尾） | 合并/回撤的中间产物，不参与分组 | 不可 |
| 系统元数据与"已删除待清理"的位置 | 回收站、系统卷信息、日志与内核目录等，收进来只会造成误伤（见本节末段） | 不可，但可**点名放行** |
| 网盘占位文件（OneDrive / iCloud Drive 等"内容还在云端"的文件） | 处理它们等于替你下载一遍 | **可**（命令行开关，见 §3.5） |
| Windows 页面文件、休眠文件、保留设备名（`CON`/`NUL` 等） | 系统独占或无法按普通文件对待 | 不可 |

**"点名放行"**：如果你把上面某个被保护的目录（或它内部的子目录）**亲自设为扫描根**，
这一轮就按你的指名照常扫描它。软件会记下"哪些根脱离了系统保护"，但这份记录目前不在界面呈现。
这个设计的意思很直白：**保护清单挡的是误伤，挡不住你的明确意图**。

## 1.4 它如何防止误删

对每个待操作文件，软件在执行前逐道过五层检查，任何一层不过就不动手：

1. **文件还在不在**：执行时文件已不存在 → 记为"跳过"（目标已达成），不算失败；
2. **还是不是扫描时那份内容**：在使用那一刻**重新打开文件、重算全量内容指纹**，与扫描结果比对。
   被改过 → **拦截**；只改过时间戳/权限但内容没变 → 放行。**不看时间戳放行**——
   时间戳相同而内容已被换掉是真实存在的现象，指纹才是证据；
3. **还是不是那个"文件本体"**：确认这个路径上现在放着的，仍是校验时的那个物理对象
  （macOS / Windows / Linux 都按各自文件系统的方式核对）。如果中途有别的程序把它换成了另一个文件
   （下载器、同步盘、你自己改名顶替），会被拦下；
4. **删除前的最后一次确认**：对永久删除、硬链接合并、软链接合并这三条"会销毁数据"的路线，
   真正动手前还会紧贴动作再核对一次；永久删除更是在内容复核之后、删除之前再多问一次
  "我刚校验过的那个对象此刻还在不在这个路径上"；
5. **Windows 专有：备用数据流检查**：含 NTFS 备用数据流的文件**一律拒绝操作**（见 §3.4）。

另外还有两条贯穿全程的规则：

- **保留项硬拦截**：你应用过保留策略之后，被标为"保留"的文件在任何清理操作中都会被后端直接拒绝，
  界面上的勾选框也置灰——即使前端出了 bug 也动不了它；
- **写前账本**：每个清理操作在动手**之前**先把完整计划写进账本（`history.db`），
  执行中逐条记录实际去向。应用中途崩溃也不会有"说不清发生了什么"的文件。

## 1.5 哪些操作能撤回、哪些不能

| 你执行的操作 | 能否在应用内"回撤" | 说明 |
|---|---|---|
| 移入回收站 | macOS / Linux **能**；Windows **不能** | Windows 的系统回收站拿不到可靠的"原路径 → 回收站落点"映射，请用系统回收站手动还原（界面上有直达按钮） |
| 移动到指定目录 | **能** | 从新位置搬回原目录；原位置被占用时换个名字落地，绝不覆盖 |
| 硬链接合并 | **能** | 拆除链接、从保留源重建独立文件 |
| 软链接合并（跨卷） | **能**，**链接已失效也能** | 数据一直在合并前的备份里，回撤不依赖链接是否还有效 |
| 永久删除 | **不能** | 文件已不在磁盘上，应用无从恢复；只能靠系统级数据恢复工具 |

两个必须知道的边界：

- **账本写不进去时会拒绝执行**：回收站/移动/硬链接/软链接这四类"承诺可回撤"的操作，
  账本故障时一律拒绝（报错「清理账本不可用」）——不能让你按"可回撤"的预期去清理却事后无从恢复。
  永久删除与 Windows 回收站本来就不可应用内回撤，不受此限制，但会明确提示留痕失效。
  遇到这个报错请**先修复/重启应用**，而不是改用永久删除硬闯；
- **回撤不自动刷新结果页**：回撤只动磁盘文件，改完之后建议重新扫描一次核对现状。

## 1.6 应用在磁盘上留下了什么

缓存和账本都放在系统配置目录下的 `FileDedup` 文件夹，**都可以安全删除**：

| 平台 | 位置 |
|---|---|
| macOS | `~/Library/Application Support/FileDedup/` |
| Windows | `%AppData%\FileDedup\` |
| Linux | `~/.config/FileDedup/` |

| 内容 | 作用 | 删了会怎样 |
|---|---|---|
| 哈希缓存（`cache.db`） | 让第二次及以后的扫描跳过"内容没变"的文件，直接复用上次结果 | 只损失速度，不影响正确性 |
| 扫描历史 + 清理账本（`history.db`） | 「记录」页的历史恢复、重扫与**回撤**的依据 | 丢失历史与回撤能力，**删前请确认没有待回撤的操作** |
| 设置（`settings.json`） | 线程数、主题、语言、默认过滤器 | 回到默认值 |

关于缓存的信任机制，用户需要知道强度的分档：复用一条缓存记录前，软件会核对
**路径与大小、修改时间、文件物理身份、四点采样内容**四项全部一致才信任；任何一项对不上就重算。
但在**不提供稳定文件索引的卷（FAT / exFAT、部分网络共享）**上，"物理身份"这一项无从核对，
缓存只是加速手段而非等价证明——这类卷上拿不准时，可在设置里清空缓存，或开启 paranoid 逐字节模式。
缓存满 50 万条时自动淘汰最久未用到的条目；缓存库万一损坏，应用会把旧库**改名隔离**后重建，
原始文件留在原地可找回，无需人工处理。

## 1.7 它明确不做的事

- **不做"近似重复"判定**：内容相似但不同（同一段视频的两个转码版本、改过一处文字的文档）不会报为重复，也没有按画面/听感找相似文件的功能；
- **不自动清理**：任何文件被处理都必须由你点按钮触发；
- **不跟随、不修复失效的软链接**：链接失效源于你的环境变化，自动"修好"可能指向错误的地方，应用只提示、由你决定（见 §3.7）；
- **界面目前没有英文**：设置里可以选中 English 并保存，但文案尚未接入多语言，界面仍显示中文；
- **不做实时目录监控**：每次清理基于一次扫描的结果快照，扫描之后文件有改动会在操作前被校验拦下，但软件不会替你"持续盯着"目录。

# 二、使用方法

## 2.1 快速上手：一次完整清理的七个步骤

1. **添加扫描目录**：点击选择目录，或直接把文件夹拖进窗口。支持多个目录；相互重叠的目录自动去重，只扫描外层那棵。
2. **（可选）设置过滤器**：按扩展名 / 大小区间 / 排除路径缩小范围（§2.2）。
3. **开始扫描**：进度分阶段推进（扫描目录 → 采样预筛 → 全量哈希 → 可选逐字节确认），支持暂停 / 恢复 / 取消（§2.3）。
4. **阅读结果**：按"可释放空间 / 单文件大小 / 文件数"排序，按扩展名筛选，分页加载（§2.4）。
5. **落定保留项**：应用一键保留策略（路径最短 / 最新 / 最旧 / 指定目录优先级）。**应用过策略的保留项才受后端硬保护**；没应用之前，界面上的星标只是默认建议（§2.5）。要限制"只动某些文件夹里的文件"或"永远不动某些文件夹"，用处理策略（§2.6）。
6. **执行清理**：回收站（推荐默认）/ 永久删除 / 移动到指定目录 / 硬链接合并 / 软链接合并（§2.7）。
7. **核对与善后**：操作结果按 成功 / 跳过 / 失败 / 已取消 四类逐项列明；需要反悔的去「记录」页回撤（§2.10）。

## 2.2 划定扫描范围：目录与过滤器

### 2.2.1 扫描根

- 多个根目录可以同时扫；某个根是另一个根的子目录时，只保留外层那个，不会重复扫描；
- 把系统保护目录（回收站、系统卷信息等）**指名**设为扫描根是允许的，见 §1.3 末段；
- 机械硬盘 / 网络盘无需手动调参：软件检测到扫描根在这类介质上时会自动降低并发，避免拖慢机器。

### 2.2.2 基本过滤条件

| 条件 | 语义 |
|---|---|
| 包含扩展名 | 留空 = 全部；如 `.jpg`，大小写不敏感 |
| 排除扩展名 | 命中即跳过 |
| 最小 / 最大大小 | 0 = 不限。设大小下限是最有效的提速手段（候选数量直接掉一大截） |
| 包含隐藏文件 | 默认排除 `.` 开头的文件与目录 |
| 排除路径（通配符） | 见 2.2.3 |
| 排除目录（精确路径清单） | 见 2.2.4 |

所有过滤条件都是"命中即丢弃、不额外报数"：被滤掉的文件不出现在任何统计里。
（网盘占位与应用过程残留**不在这组**：它们排在过滤之前单独计数，见 §3.5。）

### 2.2.3 排除路径（通配符写法）

| 写法 | 排除的范围 |
|---|---|
| `node_modules`、`*.tmp`（不含 `/`） | 任何一层路径段命中即排除 |
| `a/b`、`a/b/` | 该目录**及其全部下级** |
| `a/b/**` | 同上 |
| `a/b/*` | 仅 `a/b` 的**直接子层**，不含更深层 |
| `*/build`、`a/**/b`（通配在中间） | 严格按模式匹配，**不**自动向后代传播 |

要点：

- `\` 与 `/` 等价，三个平台结果一致；`*` 只匹配一层，`**` 跨任意层；
- 命中的**目录整棵子树不再进入**（是"根本不去读"，不只是"结果里不显示"），所以用排除目录能实打实省时间；
- **大小写**：在你这块盘**经实测确认不分大小写**的卷上，写 `Temp` 就能挡住拼成 `TEMP` 的目录；
  其余情形区分大小写。多盘混扫时按每个条目自己所在的那块盘判定，不会互相串用；
- **写错语法的模式整条不生效**（例如漏了右方括号 `build/[`）：不是"排除得少一点"，是一条都排不掉。
  软件会在**失败清单**里明确报告这一条"语法无效、整条未生效"，方向是安全的（宁多扫不漏排），但你要去失败清单看到它；
- 语法正确但**永远匹配不到东西**的模式（如倒着写的字符区间 `[z-a]`）不会被报告——判断这类情况需要完全理解通配符语义，软件刻意不做。写完复杂模式后请用结果核对排除是否真的生效。

### 2.2.4 排除目录（精确路径清单）

扫描页在通配符行之外另有一张「排除目录（含整个子树不扫描）」清单：用目录选择器添加或粘贴路径，只填目录，不支持通配符。

| 性质 | 说明 |
|---|---|
| 匹配对象 | 按**绝对路径**比较：所列目录本身及其整个子树不遍历、不读盘 |
| 路径写法 | 多余的分隔符、尾部斜杠、首尾空白会自动整理；纯空白条目按"未配置"丢弃（绝不会出现"空条目排除全盘"） |
| 大小写 | **一律区分**，不分卷。写 `Temp` 只排掉拼写为 `Temp` 的目录——这与 2.2.3 的通配符通道**不同一条口径**，别按同一套预期 |
| 你指名的扫描根不查这张表 | 排除了 `D:\proj` 又把 `D:\proj\data` 设为扫描根，`data` 照常扫（与 §1.3"点名放行"同一取向） |
| 不产生计数 | 被它挡掉的文件从未被遍历，没有任何统计数字 |
| 只在界面有 | 命令行工具**没有**这条通道；命令行要等价表达，用通配符 `a/b/**` 近似 |

★ 三张"目录清单"容易混，先分清：

| 清单 | 效果 |
|---|---|
| 2.2.4 排除目录（扫描页） | **根本不扫描**：结果集里看不到这些文件 |
| 2.2.3 排除路径通配符 | 同上，写法不同、大小写口径不同 |
| 2.6「不处理的文件夹」黑名单 | **照常扫、照常报重复、可被选为保留项**，只是任何清理永不动它 |

## 2.3 扫描进行中：进度、暂停与取消

- **进度**：文件数 + 已读字节数双口径、速度与预计剩余时间；各阶段总量自动切换，不会虚报；
- **暂停 / 恢复**：在"下一个自然边界"停下——目录遍历停在目录之间，哈希停在文件之间，逐字节确认停在组之间。恢复后回到原阶段继续；
- **取消**：走同一批边界。**如实的提醒**：没开逐字节确认时，一个正在算全量哈希的大文件要等它这趟读完才停得下来；开了逐字节确认则中断粒度细到数据块，一对超大文件也不会拖住取消；
- 取消/暂停不浪费：已算出的哈希照常写入缓存，下次扫描直接复用；取消中断的文件**不计入失败清单**；
- 内部故障（罕见）会被上报为明确的失败状态并注明阶段，不会伪装成"已取消"。

## 2.4 阅读扫描结果

- **每个重复组**列出：组内文件（路径、大小、修改时间）、单文件大小、**可释放空间 =（文件数 − 1）× 单文件大小**。
  默认按可释放空间降序；也可按单文件大小 / 文件数排序，按扩展名筛选。分页浏览，初始 2000 组，点「继续加载」每次再放 1000 组；
- **"可释放空间"是按逻辑大小算的**，磁盘真实减少量可能差很多（稀疏文件、压缩卷），见 §3.1；
- **预览**：每行有「预览」按钮——图片出缩略图、文本出开头内容（Markdown 默认渲染、可切回源码）、二进制出十六进制头；
  另有「打开所在文件夹」在系统文件管理器中定位选中该文件；
- **「隐藏非拟处理项」开关**（工具栏右侧小按钮）：打开后，按当前处理策略**不会被处理**的行
  （保留项、不在优先文件夹内、命中"不处理"黑名单）从列表里藏起；整组都没有拟处理项的组直接隐藏。
  四条性质要记住：
  1. 它显示的"会不会被处理"与「查看清单」、执行时收窄**是同一把尺子**（软件同一处判定算出来的，不会两套结论）；
  2. **纯显示层**：你的勾选、计数、命中数、执行范围一个都不变；组头统计仍按全部文件计算；
  3. 藏了多少写在组头上（如"3 个文件（已藏 2）"，悬停看原因），不会出现"另外两个不见了"式的困惑；
  4. 改了保留决策或白/黑名单后，开着开关时会自动重取当前页；当前页一个拟处理项都没有时给出明示空态与关闭按钮。
- **快捷键**（仅在结果页、无浮层时生效；焦点在输入框内不拦截）：

| 键 | 作用 |
|---|---|
| `空格` | 预览当前悬停/聚焦项 |
| `⌘A` / `Ctrl+A` | 全选当前已加载的冗余项（保留项照旧不可勾） |
| `Delete` / `Backspace` | 清除选择 |
| `Esc` | 关闭浮层；预览面板、拟处理清单、失败清单同开时一次关一层（按此顺序） |

## 2.5 决定留哪一份：保留策略

每组有一个"保留 / 冗余"标记。工具栏的「应用保留策略」一键给**所有组**落定保留项：

| 策略 | 规则 |
|---|---|
| 路径最短（默认） | 优先选**不在隐藏目录里**的那份；同等情况下取路径最短者 |
| 最新 | 修改时间最新的一份 |
| 最旧 | 修改时间最旧的一份 |
| 指定目录优先级… | 可添加**多个目录并排优先级**（↑/↓ 调整，越靠上越优先）。每组保留"最高优先级命中目录"里的那份；同目录命中多份时取路径最深的那个。目录写法对**大小写**不敏感（按所在卷的语义）；**分隔符**统一那一腿只在 Windows 成立——macOS / Linux 上 `\` 是文件名里的普通字符，`foo\bar` 不会被当成 `foo/bar` |

**星标有两层含义，务必分清**：

- **没应用过策略的组**：星标只是**默认建议**（规则同上表"路径最短"）。它只在界面上挡勾选，**后端不认**——真正执行时保不保护，取决于你有没有落定决策；
- **执行过「应用保留策略」的组**：星标是**已落定的保留决策**，后端硬拦截任何清理操作（逐个报「保留文件不可操作」）。「重置」清掉决策，退回默认建议形态。

所以：**先选定策略并点应用，再执行清理**；动手前浏览一遍每组的星标落点是否符合意图
（默认建议"路径最短"不一定等于你想要的"留哪份"）。

**「指定目录优先级」有一条必须知道的例外**：某组内**没有任何**文件落在所列目录里时，
该组不会标出保留者，因而**完全不受"保留项不可清理"的保护**。应用策略后界面会显式弹警告
「n 组没有任何重复文件位于保留目录，未标出保留项、不受保护…」——看到它就必须对这些组手动处理，不能当没发生。

## 2.6 决定动哪些项：处理策略

保留策略回答"**留哪一份**"，处理策略回答"**动哪些项**"。两者独立，可同时用；**冲突时保留策略永远优先**——
这是结构性保证（保留项在执行层被硬拒绝），不需要你做任何取舍。

工具栏第二行有「处理策略」下拉：

| 选项 | 行为 |
|---|---|
| 全部勾选项（默认） | 勾了什么处理什么，不加限制 |
| 仅勾选文件夹内的文件… | 实际处理范围收窄为 **勾选项 ∩ 位于所列文件夹内（含子文件夹）的文件** |

选中第二项后出现优先文件夹列表，可添加多个（命中其一即算，不分先后）。

**三个性质：**

1. **不改变你的勾选**：只在**执行那一刻**做过滤，勾选框状态原样不动；
2. **只能做减法**：不可能处理到任何你没勾的文件；
3. **保留策略永远优先**（见上）。

**「不处理的文件夹」黑名单**（同行并排的另一张清单）：白名单回答"处理谁"，黑名单回答"**永不处理谁**"。
目录内的文件**照常出现、照常报重复、可当保留锚点、也照常可勾选**——勾得上，执行时不动。
命中目录本身与其全部子目录。它**不牵连任何其他项**。与优先文件夹可同时开，也可只开黑名单。

**计数怎么读（三层，必须分清）**：

| 位置 | 显示 | 含义 |
|---|---|---|
| 保留策略行右侧 | 已选 **N** 项 / 共 X | 你勾选的数量与总字节 |
| 同上（收窄时追加） | 其中 **M** 项在处理范围内 / 共 Y | 真正会被处理的数量（白名单 ∩ 非黑名单） |
| 确认框 | 将处理 **M** 个文件（已勾选 N 项，其中 N−M 项本次不改动） | 点「确认」后实际发生的范围 |
| 操作按钮 | 按 M 判定禁用 | **M = 0 时所有操作按钮灰化**——宁可点不动，也不让你以为点了会做 |

两个数都要显示是刻意的：只报 40、实做 12，你会以为应用漏做了。

**要看具体是哪些文件：点「查看清单」抽屉**（有勾选项时出现）。计数只告诉你有多少，
抽屉按行给出**此刻点执行会发生什么**：

| 抽屉里看到 | 含义 |
|---|---|
| 标题「将处理 **N** 项 / 不会处理 **M** 项」 | 与上面第三层同一个数、同一处判定算出来的（不是界面自己另算一遍） |
| 「将处理」段，每行带「组 #x」 | 这一项**会**被处理；组号方便回结果页核对上下文 |
| 「以下 N 项不会被处理」分隔行 | 分页边界：第一页可能两种项都有，翻页要读完 |
| 归属「保留项 · 硬拒绝」 | 当前保留策略选中的那份，**任何操作都不会碰它**（即使它正好在优先文件夹里） |
| 归属「不在优先文件夹内」 | 勾了它，但它落在白名单外，本轮不动 |
| 归属「「不处理」目录内」 | 勾了它，但它命中黑名单，本轮不动。（同时不在白名单内又命中黑名单的项归"不在优先文件夹内"——记最先拦住它的那条） |
| 归属「已不在结果集」，路径显示 `—（ID x）` | 曾被勾选、现已不在当前结果集（例如上一轮操作后刷新过）。路径与大小**读不到**才只给编号——这是能力边界，不是 bug；这一项**不会**被处理 |

排序可按分组序 / 大小 / 路径（默认分组序），每页 50 项。**清单是打开那一刻的快照**：
改了勾选或文件夹后**重新打开**才会重取，它不会自己变。但"清单说会处理"与"实际处理"之间
不会有**判定标准**上的差异——两者问的是软件里同一份判定，差异只可能来自你在中间改了东西。

**其他必知**：

- **仅本次结果集**：优先文件夹与黑名单都**不写入设置文件**，切换结果（新扫描 / 载入历史 / 重扫）自动清空——残留会把"不该动的别动"扩大到下一份结果；
- **文件夹写错了会点名**：某个优先文件夹里一个可处理的重复文件都没有时，列表下方直接点名该文件夹、提示检查路径；
- **交集为空直接拒绝**：所有勾选项都落在范围外时，操作被拒绝并给出原因（含"其中几个文件夹内没有任何可处理项"），**不会静默执行 0 项**；
- **数没算出来会明说**：确认框里的数来自一次实时判定，失败时直接显示原因并给「重新计算」按钮，不会停在"正在核算…"装忙。两种状态下确认按钮都是灰的——宁可不说数，也不说猜出来的数。

**典型用法**：只清备份盘上的副本（优先文件夹填备份盘路径）；先清下载目录；确认某目录里到底有没有可清理的重复（只填它，看计数是否 0）。

## 2.7 五种清理操作

| 操作 | 做什么 | 安全机制与限制 |
|---|---|---|
| 移入回收站（推荐默认） | 放进系统回收站 | macOS 经访达、Windows 走系统回收站接口、Linux 按 freedesktop 回收站规范自研实现（不依赖桌面组件）。批量失败自动退化为逐个执行并隔离出错项；可随时取消。**Windows 有额外两道防线，见 §3.2** |
| 永久删除 | 直接删，**不可恢复** | 必须显式勾选确认标志，无确认拒绝执行；动手前照常走 §1.4 全部校验，且删除前再多问一次身份 |
| 移动到指定目录 | 把冗余项挪进你指定的文件夹 | 目标目录必须是**本会话内经目录选择器授权过**的路径（拒绝任意路径）；而且**每个文件动手前还会按它将要落到的那个具体位置再核一次授权**（2026-09-24 起）——目标目录在操作进行中被别人换成链接或改名时，那一条会**失败并保持源文件原地不动**，不会顺着新位置写到别处去。同卷是改名（瞬间完成）；跨卷是"复制 → 校验字节数 → 落盘 → 还原权限与时间 → 删源"，任何一步失败**保留源文件**，且失败提示会把已复制副本的**实际路径写出来**让你去核对。重名自动加 `_1` 递增，不覆盖。逐个**串行**执行（并发移动同名文件会有覆盖竞态，安全优先于速度）。注意：跨卷复制不重算内容哈希（内容核对在动手前的校验里已经做过）；属主与扩展属性不还原 |
| 硬链接合并 | 把内容相同的多个文件并成一份物理数据、多个名字，占的空间随"最后一个名字被删"才释放 | 合并前对两边各做内容与物理身份校验，防"校验后被替换"反向覆盖。**仅同一卷内可用**（文件系统限制，跨卷必失败）。合并留下的小备份文件成功即删；删不掉时以「提示 N」告知、不影响合并本身（见 §3.8） |
| 软链接合并（跨卷） | 冗余位置换成一个"指针文件"指向保留源，数据只留一份、原路径仍可打开 | **仅当已加载的结果里存在跨卷重复组时才出现这个按钮**（同卷请用硬链接，那是严格更优解）。与硬链接同等的安全流程 + 终局复核。代价与权限见下 |

**软链接合并的代价（务必理解）**：软链接指向的是**路径**，不是数据——

| 情况 | 后果 |
|---|---|
| 删除 / 移动保留源文件 | 所有链接失效（打不开） |
| 保留源所在磁盘未接入（移动硬盘拔了） | 所有链接失效 |
| 保留源所在盘符被重新分配 | 链接可能指向错误的文件 |

硬链接没有这个问题：它是同一份数据的第二个名字，删掉任何一个名字数据都还在。

**使用建议**：把**不会移动的盘**上的那份设为保留项（先用"指定目录优先级"策略落定）；
合并后如需反悔，在「记录」页点「回撤」——**链接已经失效了也能回撤**（数据在合并前的备份里）。

**Windows 权限**：创建符号链接默认需要管理员权限或开启「开发者模式」（设置 → 系统 → 开发者选项），
二者都没有时改用硬链接（仅限同卷）。三者都不满足时操作整体失败、**不会有任何文件被改动**，
结果条只给一条汇总指引。文件系统层面：NTFS / ReFS 支持，**FAT / exFAT 不支持**（会明确报"该卷不支持符号链接"）。

## 2.8 读懂操作结果

每次操作的结果分四类逐项列明：

| 状态 | 含义 |
|---|---|
| 成功（OK） | 执行成功。注意**字节数按操作类型分栏，不是都算"释放空间"**：永久删除、移出本卷的计「已释放」；进回收站的单列（文件还在盘上，同卷只是一次改名）；硬链接、软链接合并也各列一栏（当期不释放空间）。⚠️ 已知问题：**同卷"移动"目前也被计进「已释放」**，那是登记在案的统计口径缺陷，看到时请按"改了个名"理解 |
| 跳过（Skipped） | 执行时文件已不存在——目标已达成，不算失败 |
| 失败（Failed） | 校验拦截或系统错误，逐项注明阶段与原因 |
| 已取消（Cancelled） | 取消后没来得及执行的条目，不会从结果集中移除 |

成功/跳过的文件会从结果集中移除；组内不足 2 个文件时整组消失。

**失败清单**（统计条「失败项 N」点开）里每行有两个按钮：**打开该项**（用系统默认应用打开这个路径本身）与
**打开所在文件夹**（在访达 / 资源管理器 / 文件管理器中定位选中）。注意：点了报「路径不存在或无法访问」
是**点击那一刻**的实况——失败记录里的路径可能早已被别的程序删掉或移走，不代表当初的失败原因变了。

## 2.9 扫描历史：恢复与重扫

每次**成功完成**的扫描自动保存一条结果快照到「记录 → 扫描历史」（最多 20 条，超出淘汰最旧）：

- **恢复**：把历史结果重新载入为当前结果集，直接继续清理。载入不碰磁盘；陈旧问题由操作前逐文件校验兜底——
  已被修改的拦截、已消失的按跳过处理。结果页顶部会挂「当前为历史结果」横幅；
- **重扫**：按那条历史的配置（目录 / 过滤器 / 线程数 / 逐字节确认）重新发起扫描；
- **联动裁剪**：在恢复的历史结果上继续清理后，该历史行的数字同步更新（原始快照保留展示为"已清理 n"）；
- 你落定的保留决策（含"指定目录优先级"的结果）随历史保存，恢复后不丢；
- 删除/清空历史只影响账本，不影响磁盘文件与当前结果集；
- 扫描页顶部有「上次扫描 <时间>」横幅，给 恢复 / 查看历史 快捷入口。

## 2.10 清理记录与回撤

「记录 → 清理记录」列出每次操作的时间、类型、条数、已回撤数与空间数字，点「明细」逐文件查看状态。

- **全部回撤**：记录行点「回撤」（二次确认），一次恢复该记录全部"已执行"条目；
- **单项回撤**：明细里逐行点「回撤」只恢复该文件；「回撤失败」的条目给「重试回撤」，
  修正外部状况后可单独再试（重复点也安全）。若某行**根本没被受理**（例如上一条回撤还在跑），
  按钮会立刻回到「回撤」，不会假装"执行中"。

回撤与正向操作同等严格：

1. 只处理"已执行"条目；已回撤/失败/跳过的不重复动；
2. 回收站/移动回撤的前提是落点文件仍在且大小与记录一致，且**动手前会紧贴改名动作再核对一次落点身份**
  （落点被第三方文件顶替时拦截、原位不动）；**原位置已被占用时不覆盖**，改以 `名称.fdd-restored.扩展名`
   落地。若落点已空、但原位置有一份尺寸/时间/内容全部吻合记录的文件，判为"上次回撤其实已生效"，直接记成功；
   跨卷复制回来但删不掉原处文件时，盘上会短暂有两份——失败提示会**写出副本的实际路径**；
3. 硬链接回撤三重防线：目标必须仍指向那个物理文件（被换成别的文件即拦截；若已独立成文件且内容吻合记录，
   判为已回撤）；从保留源复制的内容必须整份重算指纹吻合；全过才原子替换，失败时现状分毫不动；
4. 软链接回撤：目标位置必须仍是**指向原保留源的链接**（你自己换成别的文件即拦截）；备份必须存在；
   数据本体重来不在链接里，所以**链接悬空照常可回撤**；
5. 回撤不清掉执行账本、也不自动改结果页——恢复完成后请**重新扫描**刷新；
6. 「清空记录」会连带丢弃回撤能力，二次确认时明确警示；**清理/回撤进行中一律拒绝清空**，按钮置灰；
7. 清理/回撤进行中，「应用保留策略」「重置保留决策」「开始扫描」「回撤」等入口统一被拒、按钮置灰——
   避免出现"界面以为已重置、磁盘上仍按旧决策执行"两套事实。

**应用在执行中被强杀**：重启后未落账的条目收口为**中断**徽标，提示你去文件系统核对现状；
回撤中途死掉则收口为**回撤失败**并写明"结果未落账"，点「重试回撤」会按磁盘现状复核，文件确实已回家就记成功，不会误报。

## 2.12 命令行工具 fdd-cli

批量/脚本场景用的命令行版，输出 JSON 报告：

```
fdd-cli [选项] 目录...

  -threads N        工作线程数（0 = 默认，按核数自动）
  -paranoid         逐字节确认
  -min-size N       最小文件大小（字节）
  -max-size N       最大文件大小（0 = 不限）
  -exclude LIST     排除扩展名，逗号分隔，如 .tmp,.log
  -hidden           包含隐藏文件
  -allow-cloud-hydration
                    允许读取云端占位文件（会触发按需下载，见 §3.5）
  -o FILE           输出到文件（默认屏幕输出）
  -cache PATH       哈希缓存文件路径（不传 = 禁用缓存；可与界面版共用同一个缓存文件，跨次运行复用）
```

**注意**：命令行**没有**界面上的"排除目录（精确路径）"通道，要等价表达请用通配符 `-exclude` 的目录模式近似；
也没有处理策略/清理功能——它只做检测，清理仍在界面版完成。

报告含统计（文件总数 / 失败数 / 组数 / 可释放字节 / 重复文件数 / 系统保护跳过数 / 云端占位跳过数 /
过程残留跳过数）、全部分组与失败清单。两个计数读法：

- `stats.skipped_cloud_files`：本轮**没参与去重**的云端占位文件数。它为 0 有两种含义——盘上确实没有，
  或者你加了 `-allow-cloud-hydration`（那一档照常读取、不再计数）。它不计入"文件总数"、也不算失败；
- `stats.skipped_work_temp_files`：按**名字形态**判为过程残留、未参与去重的文件数。
  判据只看名字（以 `.fdd-old` 等结尾、或名字里插着 `.fdd-restored`），分不出"应用自己的残留"与
  "恰好这样命名的你的文件"——后者同样被跳过、同样计入这个数。确认是不是残留，看内容是否与某个保留源逐字节相同。

# 三、注意事项与排错

## 3.1 "可释放空间"和磁盘真实减少量是两回事

界面上的"可释放"按文件**逻辑大小**计算，磁盘真正减少的是**实占空间**。两者对不上是正常物理现象，不是漏算：

- **稀疏文件**：一个"8 GiB"的虚拟机磁盘可能只实际落了 120 MiB——按逻辑计会把收益报大几十倍；
- **NTFS 压缩卷 / 预分配文件**：方向同理，实占甚至可能**大于**逻辑大小。

命令行报告两个口径都给（逻辑口径与实占口径）；**界面结果页目前只显示逻辑口径**，
历史记录的数字也一律是逻辑口径（恢复历史时不显示实占——库里没存过这个口径，不拿逻辑值冒充实测）。
核对清理效果请以磁盘容量变化或命令行实占口径为准。

## 3.2 Windows 上"移入回收站"是全流程里最需要警惕的一步

Windows 的系统接口有一个**官方文档未写明**的性质：**文件进不了回收站时，系统不报错，而是直接永久删除，并返回"成功"**。
不加防备的后果：文件从原位置消失、回收站里什么都没有、界面显示一切正常。典型触发条件：

| 触发条件 | 说明 |
|---|---|
| **单个文件超过回收站容量** | 回收站默认上限约为卷容量的 **5%**。跨硬盘去重常见的几十 GB 镜像/视频/安装包，**一个文件就能超过整个回收站容量**——这是本软件用户最容易撞上的场景 |
| 回收站被系统策略禁用 | 包括**全局**和**按卷**两处设置（在回收站属性里对单个盘勾掉"移到回收站"就是后者）。软件两处都查 |
| 该卷回收站目录不可用 | 被安全软件接管/清理、权限异常等 |

**软件的两道防线**：

1. **事前预检**：逐文件检查卷类型、回收站是否被策略禁用、**单文件是否超过该卷回收站容量上限**。
   任一不满足**整批拒绝**并说明原因，建议改用「移动」或自行确认后「永久删除」。网络盘 / 不可回收的卷直接拒绝。
2. **事后复核**：系统返回"成功"之后，再独立核对两件事——源路径确实消失了，且该卷回收站条目数的增量
   对得上本轮预期入站数。验不过即报错，**不会**替你显示成功。
   如实的边界：复核需要事前能查到该卷的条目数作基准。事前查不到（移动盘当时休眠/拔线等）时，
   该卷本轮只核"源消失了"这一条——"源没了但回收站里也没有"这一类**检不出来**、界面会显示成功。
   对已挂载可查的盘不受影响；这是登记在案的已知缺口。

**看到这条提示时怎么办**——「文件已从原路径消失，但未能确认其进入回收站」：

1. **立刻**打开系统回收站核实（界面上有直达按钮）；
2. 文件在里面 → 右键"还原"取回，之后改用「移动」操作；
3. 不在里面 → **停止对该盘的一切写入操作**，尽快用数据恢复工具抢救（写入新数据会显著降低恢复成功率）。

**建议**：跨硬盘处理大文件时，优先用「移动」到目标目录（不受回收站配额限制），
或先手动调大该盘回收站容量（右键回收站 → 属性 → 选中该盘 → 自定义大小，设为大于最大单文件的值）再回收。

另外：Windows 回收站**不支持应用内回撤**（§1.5），"打开系统回收站手动还原"就是它的反悔路径。

## 3.3 看到"文件在扫描后被替换/修改，已拦截"＝保护生效了

这类提示是 §1.4 那道校验抓到了"扫描之后文件变了"，是**保护行为，不是软件故障**。措辞分三档，处置相同：

| 提示说的是 | 实际发生了什么 |
|---|---|
| 被换成另一个文件（确认） | 这个路径上现在放的是**另一个文件**——删它就会丢别人的数据 |
| 文件已消失 | 位置上空了，可能是你自己或别的程序删的——按"跳过"处理，不算失败 |
| 无法确认（读不出原因） | 软件**不知道**它还是不是原来那个——宁可拦一次让你重扫，不放行一次可能覆盖他人文件的操作 |

三种都不动盘上一字节。正确处置：**重新扫描**后再决策。最常见的成因：扫描后你（或同步盘、下载器、编辑器）
动过这些文件；扫描结果是几分钟/几小时前的一份快照，中间窗口越长越容易被撞上。

要知道的代价与边界：

- 永久删除 / 硬链接 / 软链接这三条销毁数据的路线，动手前会把文件内容**再整份读一遍、重算一遍指纹**。
  大批量清理时会明显多花时间（量级：每 100 GB 冗余约多花几十秒），这是"看得见才动手"这道保险的价格，不是回归。
  移动与回收站不做这次额外读盘（移动不销毁内容、回收站随时可回撤）；
- "校验通过之后、执行之前"的毫秒级窗口在理论上不可能完全归零（除非独占所有相关文件，那不是通用清理工具该做的事）。
  最坏残余是：这期间被换成**另一份内容完全相同**的文件——删它不丢数据，只是"释放空间"统计偏乐观。

## 3.4 带"备用数据流"的文件会拒绝一切清理（Windows）

NTFS 上一个文件名下除了看得见的正文，还可能挂着 `f.txt:note`、`报告.docx:Zone.Identifier`
这类**备用数据流**。删除与合并只带走正文，附流的会随之消失且无处找回。所以软件在动任何文件前
先枚举它的全部数据流，**只要有命名流就整项拒绝**（记失败，提示「文件含备用数据流，去重会丢失备用流内容，已拒绝操作」），
**文件分毫未动**。五种操作一视同仁。

想处理只能手工来：用 `dir /r` 看清流列表、确认内容不再需要（要留的先导出）、删流，然后重新扫描。

两条边界要如实知道：

- 判据只看"有没有命名流"，**不看流的内容**——两个正文相同、备用流不同的文件**仍会被报成重复组**（只是清理会被拒）；
- 这道检查只有 Windows 有语义，其他平台恒不触发；流列表"读不出"（拒绝访问等）时同样拒绝——与"宁可拦一次"同一取向；文件已不存在或该卷本就不支持流（FAT/exFAT）则放行，交给正常流程判定。

## 3.5 网盘占位文件（OneDrive / iCloud Drive）默认被跳过

同步盘在本地常放"只有元数据、内容还在云端"的占位文件。去重必须读内容，**读它就等于替你下载一遍**
（一个几百 GB 的云盘目录能在几分钟内把流量跑满）。所以默认跳过并**单独计数**（§2.12）。
**界面上目前没有"已跳过 N 个云端占位"的提示横幅**，这个数目前只能在命令行 JSON 报告里看到。

要让它们照常参与：命令行加 `-allow-cloud-hydration`——注意代价是**按需下载真的会发生**（哈希阶段要读文件内容），
且这一档下"云端跳过"计数恒为 0（没有跳过这件事，就不报跳过的数）。Linux 上的 rclone/gvfs 挂载
没有统一的占位语义，这一条恒不触发，按普通文件处理。

## 3.6 FAT / exFAT 与部分网络卷的特殊性

这类卷不提供稳定的文件索引（或卷行为不可靠），几处防线会相应降级，用之前请知道：

- **缓存复用**：§1.6 说的"物理身份"一道无从核对，正确性只剩"大小 + 时间 + 四点采样"三道。采样全等而内容其实不同理论上仍可能——这类卷上缓存是**加速手段而非等价证明**，拿不准就清空缓存或开 paranoid；
- **删除前"还是不是那个文件"的核对**：这类卷上留不下可比的身份底片，这一格按"与上一次核对同一个"放行，兜底靠内容指纹；
- **软链接**：文件系统不支持，会明确报错；
- **排除目录的大小写**：这类卷若经确认为"不分大小写"，通配符排除会放宽（写 `Temp` 挡掉 `TEMP`）；判不准时一律区分大小写——排除范围**不随证据缺失而扩大**；
- **符号链接**：不跟随、不参与分组（所有平台如此）；
- Windows 长路径：应用声明了长路径支持，但真机超 260 字符路径未复测、且需系统开启长路径策略才生效——路径特别深的仓库类目录建议缩短后测。

## 3.7 链接合并的长期代价

**硬链接合并后**：所有路径共用同一份数据。**修改任何一个路径的内容，会影响所有名字**——
只对"纯占地方、永不再单独编辑"的副本使用。删除任何一个名字只是少一个入口，数据在最后一个名字被删时才真正消失。
"释放空间"也因此是**将来时**：合并当期几乎不释放什么，收益发生在之后删冗余名字的那一刻。

**软链接合并后**：见 §2.7 的失效表。想知道哪些链接已经失效：去「记录」页展开该笔操作明细，
失效条目整行标红并显示「链接已失效」，悬停看目标路径与建议。**应用不会自动修复**（失效源于你的环境变化，
自动"修好"可能指向错误的位置），但**失效也能回撤**（§1.5）。

**下次扫描不会把链接当成重复文件**：符号链接一律跳过（不可关闭），失效链接同样。

## 3.8 容易被误认为异常的正常现象

| 现象 | 是什么 |
|---|---|
| 扫描根 / 优先目录里一闪而过 `.fdd-case-probe-<数字>` 隐藏文件 | 软件在**实测这块盘分不分大小写**（写一个临时文件、换个大小写去认它），测完立刻删除。只读盘、无写权限的盘不会创建它；异常退出留下的话可直接删除 |
| 合并后残留 `.fdd-old` 结尾的文件、结果条显示「提示 N」 | 合并前的原始备份该删没删掉（多半被别的程序占用）。链接已合并成功，残留可手动删，也可留着（占一份空间，数据与保留源相同）。这类名字**下次扫描会被无条件忽略**，不会变成"幽灵重复文件" |
| 「已选 40 项」但按钮灰着 / 确认框说"将处理 12 个" | 处理策略在收窄范围（§2.6），两个数落差是刻意展示的 |
| 恢复历史结果后清理，个别文件报"已被修改/已消失" | 操作前校验在兜底（§3.3），历史快照陈旧是预期内的事 |
| 「记录 → 清理记录」某条标着「不可回撤」 | 永久删除；或 Windows 回收站（系统接口拿不到可靠落点）。走各自的手动路径（数据恢复工具 / 系统回收站还原） |
| 点「查看清单」里的行路径显示 `—（ID x）` | 该项已不在结果集（§2.6），读不到路径了，不会处理它 |
| 结果比文件数少一截（网盘目录） | 云端占位被跳过并单独计数（§3.5） |
| 两个文件内容一样、大小不同，没判重复 | 大小不同内容必然不同（差多半是行尾/编码/元数据）。软件不做"近似重复"（§1.7） |

## 3.9 提示语速查：这条提示什么意思、该怎么办

**先读懂提示的形状**（2026-09-24 起）：扫描/清理异常中断的提示统一是「**中文说明**（系统原文：…）」。
前半段是给你看的，括号里那段是操作系统或运行时的原话，**原样保留、含绝对路径**，为的是能复制去搜索或发给帮你排查的人。
所以看到英文不要以为是软件坏了两截——中文部分才是软件的判断，英文部分只是证据。⚠️ 截图外发前留意原文里的目录结构。
（下表列的是常见中文外壳的含义；应用自己写的拦截句不做二次包装，你在界面上看到的就是它本身。）

| 提示（关键词） | 含义 | 处置 |
|---|---|---|
| 权限不足，无法访问该位置 | 系统拒绝了读写（原文多为 `permission denied` / `Access is denied`） | 检查该目录的所有者与访问权限；Windows 上可能要管理员运行（§2.7） |
| 该文件或文件夹已不存在 | 动手那一刻目标没了（原文 `no such file or directory` / `The system cannot find the file specified.`） | 属正常竞态（别的程序或你手动移走），重新扫描即可 |
| 正被其他程序占用 | 文件被编辑器、同步盘、杀毒等握着手柄 | 关掉占用程序再重试；同批次其他项可能同样失败 |
| 所在卷是只读的 / 目标卷空间已满 | 卷状态问题，与软件无关 | 挂载改为读写 / 清理目标卷空间 |
| 路径过长，超过文件系统上限 | 路径超过长度上限 | 把内容挪到更浅的目录再操作 |
| 操作已取消 / 操作超时 | 取消或超时中断，不是内容错误 | 需要就重扫；大卷上的超时通常与设备速度有关，与重复判定无关 |
| 应用内部异常已被拦截，本次操作中断 | 内部异常被守卫吞下、进程没崩，但**这一次操作没有正常收尾**（原文含 `goroutine panic`） | 已派发的条目可能改到一半：按 §2.10 的中断口径去文件系统与「清理记录」核对现状，再重新扫描决策；原文里的栈信息发给排查的人 |
| 移动目标在操作期间被替换…已不在授权目录内 | 你选的目标文件夹在清理进行**中途**被别的程序改名/移走，或换成了指向别处的链接——落点已跑到授权范围之外 | **该条源文件原地未动**、什么都没写出去。确认那个文件夹还在原位后重新点一次移动即可（§2.7） |
| 操作未能完成（未分类的系统错误） | 系统给了一句软件认不出的话 | 看括号里的原文判断，或直接按原文搜索；**不假装知道**是这条提示的设计 |
| 清理账本不可用，已拒绝执行 | 回撤依据的账本写不进，"承诺可回撤"的操作一律停摆 | **重启应用**让账本自愈（损坏时会被改名隔离后重建）再重试；**不要**改用永久删除硬闯——那是唯一还放行的路径且不可恢复 |
| 文件已从原路径消失，但未能确认其进入回收站 | Windows 事后复核没通过，文件可能已被直接删除 | 立刻开回收站核实；没有就停止写入、上数据恢复工具（§3.2） |
| 单文件超过该卷回收站容量上限 | 事前预检拒绝整批回收 | 三选一：改用「移动」；调大该盘回收站容量；确认不需要后用「永久删除」（§3.2） |
| 文件在扫描后被替换 / 被修改，已拦截 | 操作前校验抓到变更 | 重新扫描再决策（§3.3） |
| 文件含备用数据流，已拒绝操作 | NTFS 附流保护 | 手工清流后再扫（§3.4） |
| n 组没有任何重复文件位于保留目录 | 这些组没有保留者、**不受保护** | 对它们手动勾选，或换保留策略（§2.5） |
| 所选文件均不在「优先处理的文件夹」范围内 | 交集为空 | 检查文件夹路径（界面会点名零命中的那个）；或切回「全部勾选项」（§2.6） |
| 排除模式语法无效，整条未生效 | 你写的通配模式有错（如漏右括号） | 去失败清单看原文，修正写法重扫；不修的话该条**什么都排不掉**（§2.2.3） |
| 需要权限 / 开发者模式（软链接） | Windows 创建符号链接的权限不足 | 管理员运行 / 开开发者模式 / 同卷改用硬链接；失败时**没有任何文件被改动**（§2.7） |
| 该卷不支持符号链接 | 目标是 FAT/exFAT 等 | 换 NTFS 位置或改用其他操作（§3.6） |
| 回撤：原位置已被占用 | 你或别的程序在那个位置放了文件 | 软件已改用 `名称.fdd-restored.扩展名` 落地，不会覆盖；去原位置或新名字处核对（§2.10） |
| 中断徽标 / 「结果未落账」 | 应用曾在执行中被打断 | 去文件系统核对现状；回撤类条目点「重试回撤」，软件会按磁盘实况复核（§2.10） |
| 打开该项 / 打开所在文件夹：路径不存在或无法访问 | **点击那一刻**该路径已没了 | 属实况，不代表失败原因变了；需要就重新扫描定位现状（§2.8） |

## 3.10 推荐的使用流程

1. **第一次先小范围试**：挑一个你有把握的目录跑完整流程，熟悉"应用保留策略 → 查看清单 → 回收站 → 回撤"这条链路，再上大目录；
2. **重要数据**：扫描时开 paranoid（逐字节确认）；首次大范围清理用**回收站**，观察几天再清空回收站；
3. **动手前**：确认保留策略已"应用"（星标才受后端保护，§2.5）；勾得多时点一次「查看清单」抽查；
4. **跨硬盘大文件**：优先「移动」而不是回收站（§3.2）；
5. **链接合并**：硬链接只用于"永不再单独修改"的副本；软链接只用于跨卷，且保留源选**不会移动的盘**；
6. **扫描效率**：用排除路径剪掉 `node_modules`、`.git`、`build` 这类目录（整棵跳过，省的是遍历时间）；
   用扩展名 / 大小下限缩小候选；机械盘与网络盘不用调线程数（自动降档）；
7. **缓存**：第二次扫描才见提速（未变化的文件复用哈希，复用前仍做安全比对，不为速度牺牲正确性）；
   大规模搬移目录树后旧路径条目会自然淘汰，想立刻清可去设置里「清空缓存」（两段式确认）；
8. **善后**：清理完、回撤完，都**重新扫描一次**核对现状。

## 3.11 常见问题

**Q：为什么 0 字节文件和符号链接不出现？**
内置跳过，防"空文件假组"与链接环路，不可关闭（§1.3）。

**Q：文件被我改过但修改时间没变，会不会被误删？**
不会。操作前重算内容指纹比对（§1.4、§3.3），时间戳不参与放行判断。

**Q：硬链接的多个路径为什么只显示一个？**
同一份物理数据只计一次，否则"可释放空间"是虚数。想给它们省空间，用「硬链接合并」处理的是**内容相同的不同文件**，不是一回事。

**Q：移动操作为什么比其他操作慢？**
移动是逐个串行执行的——并发移动同名文件会产生覆盖竞态（静默数据丢失），安全优先于速度（§2.7）。

**Q：取消扫描后刚才算的哈希白算了吗？**
没有。取消路径同样写回缓存，下次扫描直接复用（§1.6、§2.3）。

**Q：回撤成功后，为什么结果页还显示那些文件？**
回撤只动磁盘、不改结果页（结果是扫描时的快照）。看到「回撤完成」后重新扫描一次即可刷新（§1.5、§2.10）。

**Q：为什么有的重复文件组里没有「软链接合并」按钮？**
它只在已加载结果里**存在跨卷重复组**时才出现。同卷刻意不显示：硬链接是零权限、无失效风险的严格更优解，
多给一个"能用但更差"的选项只会误导。若你确信有跨卷组而按钮没出现，可能是该组的卷标识未能解析
（部分文件系统不提供稳定索引），软件选择不出按钮而不是冒险猜测（§2.7）。

**Q：软链接合并后我把保留文件删了/移走了，数据丢了吗？**
没丢。数据本体一直在合并前的备份里：保留源还在别处 → 删掉链接或点「回撤」恢复独立文件；
保留源确实删了 → **该条目照样能回撤**，回撤后你拿到一份合并前的完整文件（§2.7、§2.10）。

**Q：历史恢复出来的结果安全吗？**
安全。载入历史不碰磁盘，之后每个清理动作仍走操作前逐文件内容校验（§2.9、§3.3）。

**Q：想让界面变成英文？**
目前只有中文。设置里可选中 English 并保存，但界面文案尚未接入多语言（§1.7）。
