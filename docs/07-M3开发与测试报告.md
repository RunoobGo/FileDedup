## 3. 开发过程缺陷与修改记录

### D12（高·设计返工）：executor 首版设计混乱

- **现象**：首版用全局变量 reverseIndex + 占位函数拼装"文件→组保留者"路由，含死代码与误导性注释
- **处置**：立即重写——构建 `keepSrcByID` 反向映射（组遍历时一次填充），删除全部 hack；无行为缺陷（编译前重写），记录为设计纪律问题

### D13（中·语义）：keepShortest 平局规则未定义

- **现象**：集成测试失败——两个等长路径（u/a1.bin vs v/a2.bin）平局，pickShortest 保留首个，与测试断言不符
- **处置**：确认平局规则（保留遍历序首个=路径排序后字典序最小，稳定可解释）为最终语义；**修正测试数据**（制造明确最短路径），并在报告中固化该规则：**shortest 平局时保留字典序最小者**

### D14（中·测试隔离）：S1 触碰真实系统回收站

- **现象**：TestS1 首版未注入 mockTrash，osascript 调用真实 Finder（沙箱内挂起 15s + 权限弹窗风险）
- **处置**：全部安全测试统一注入 mockTrash（成功/失败可控）；**真回收站仅由用户环境手测触发**（L4 checklist）
- **教训**：涉及系统副作用的测试必须接口注入隔离——TrashFn 可注入设计从第一天就该用于所有用例

### D15（低·代码质量）：executor 结果集清理含 no-op 残留

- **现象**：`delete(a.byID, 0) // no-op` 占位代码
- **处置**：清理为明确的 gone 集合判断

### 备注（环境）

- wails build 每次生成 `frontend/wailsjs/`（本项目用手写桥不需要）：构建后清理，不影响产物
- S7 曾出现 osascript 在测试沙箱"意外成功"的偶然行为——正是 D14 修复的动机
