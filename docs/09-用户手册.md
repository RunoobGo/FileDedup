## 1. 产品概述

FileDedup 是一款**按内容识别重复文件**的桌面工具，核心保证是：

- **内容级判定**：只有完整内容完全一致的文件才会被分为一组，文件名相似但内容不同的一律不报。
- **操作前校验**：任何清理动作执行前都会重新校验文件内容，扫描后文件被修改过则拒绝操作。
- **默认可回滚**：默认走系统回收站，永久删除需要显式二次确认。

内置行为（不可关闭）：

| 行为 | 说明 |
|---|---|
| 跳过符号链接 | 不跟随链接，避免环路与重复计数 |
| 跳过 0 字节文件 | 空文件无内容语义，不参与分组 |
| 硬链接只计一次 | 同一物理文件（同 inode/FileId）的多个路径不会互相判为重复 |

## 2. 快速上手

### 2.1 启动

```bash
cd /Volumes/fx/Object/FileDedup && wails dev     # 开发模式
# 或使用构建产物直接运行
```

窗口默认 1180×780，最小 920×620。

### 2.2 一次完整清理流程

1. **添加扫描目录**：点击选择目录，或直接把文件夹拖入窗口（支持多根目录；重叠根会自动去重，只扫描外层）。
2. **设置过滤器**（可选）：按扩展名 / 大小区间 / 排除路径缩小范围。
3. **开始扫描**：进度条分阶段推进（扫描目录 → 预筛哈希 → 全量哈希 → 可选逐字节确认），支持暂停 / 恢复 / 取消。
4. **阅读结果**：按"可释放空间 / 单文件大小 / 文件数"排序，按扩展名筛选，分页加载。
5. **决定保留项**：逐组勾选，或应用一键保留策略（保留项受保护，任何操作都不会动它）。
6. **执行清理**：回收站（默认）/ 永久删除 / 移动到指定目录 / 硬链接合并。
7. **查看反馈**：操作结果分 OK / 失败 / 跳过 / 已取消四类逐项列明，失败项进入统一失败清单。

## 3. 检测算法详解

整个检测是一条**多阶段漏斗**（`internal/dedup/pipeline.go`），每一层都只淘汰"不可能重复"的文件，逐层把读盘量压到最低：

```
全部文件
  │ 阶段 0  元数据扫描（并行遍历目录）
  ▼
按文件大小分组 ── 独享大小的直接淘汰（大小不同内容必不同）
  │ 阶段 1
  ▼
候选文件（大小 ≥2 个的组）
  │ 阶段 1.5  FileKey 去重（硬链接只保留一个路径）
  ▼
按 (size, 4 点采样指纹) 分桶 ── 采样唯一桶直接淘汰
  │ 阶段 2  四点 xxHash64 预筛
  ▼
同采样桶内成员 ≥2 的文件
  │ 阶段 3  全量 BLAKE3-256（只补算缺失者）
  ▼
按 (size, 全量哈希) 聚合 → 重复组
  │ 阶段 4（可选 paranoid）逐字节比对最终确认
  ▼
输出结果
```

### 3.1 阶段 0：并行目录扫描（`internal/scanner`）

- 固定 worker 池遍历，worker 既是消费者也是生产者（发现子目录继续入队）；采用**无界目录队列 + 条件变量**，从根上消除有界队列的死锁风险。
- 大小写折叠去重：重叠根（如同时选了 `a` 和 `a/b`）只保留外层；大小写不敏感文件系统上 `A` 与 `a` 视为同一目录。
- 目录级剪枝：命中排除模式的目录**整棵子树不再进入**（详见 §5.3），"排除"不仅省结果，更省遍历时间。
- 每个文件记录：路径、大小、mtime（纳秒）、小写扩展名、平台 FileKey（unix 由 lstat 顺带取得，Windows 仅对候选文件按需解析）。

### 3.2 阶段 1 / 1.5：大小分组与硬链接去重

- **大小分组**：大小不同 → 内容必不同，这一层零读盘淘汰绝大多数文件。
- **FileKey 去重**：同一物理文件（unix: 设备号+inode；Windows: 卷序列号+FileId）出现在多个路径时只保留一个代表（路径较短者），然后重新检查各组是否还剩 ≥2 个成员。因此**硬链接的多个路径永远不会互判为重复**，"可释放空间"统计也因此不含虚数。

### 3.3 阶段 2：四点采样预筛（`internal/hasher`）

对每个候选文件按采样点最多读 **4 × 64 KiB = 256 KiB**：

| 文件大小 | 做法 |
|---|---|
| ≤ 128 KiB（小文件） | 读全文件，**一趟**同时算出采样指纹与 BLAKE3-256（预筛即全量，后续无需再读） |
| > 128 KiB（大文件） | `ReadAt` 读 4 个 64 KiB 采样点，各算一个 xxHash64：**头部**（偏移 0）、**中段** `size/2`、**后段** `3size/4`、**尾部**（`size − 64 KiB`；不足处钳制） |

分桶键为五元组 `(size, head, mid1, mid2, tail)`。设计依据：内容不同的文件在大小与 4 个分散采样点同时撞车的概率可忽略；而内容相同的文件五者必然相同——**保证零漏报**。中段采样还使"首尾相同、仅中间被改"的篡改可被指纹识别，这是缓存命中比对可信的前提（§4.3）。

### 3.4 阶段 3：全量 BLAKE3-256

只对"同采样桶内成员 ≥2、且还没有全量哈希"的文件读全文件：

- ≤ 512 MiB：1 MiB 块顺序流式哈希。
- > 512 MiB：**16 MiB 分段预取流水线**——后台协程按段预读（深度 2），主协程按段序喂入单一 BLAKE3 Hasher，IO 与计算重叠；段缓冲用 depth+1 环形池复用，分配次数与文件大小解耦。结果与顺序读取**逐位一致**（由等价性测试保证）。

最终按 `(size, BLAKE3-256)` 聚合出重复组。BLAKE3-256 的碰撞概率在工程上视为 0，因此**哈希相同即认定内容相同**；对不可容忍任何理论风险的用户，可开启 paranoid 模式（§3.6）。

### 3.5 并发与资源模型

| 项 | 默认 | 上限 | 说明 |
|---|---|---|---|
| 扫描线程数 | 0 = 自动 | 64 | 自动 = 核数 − 1；检测到扫描根在机械盘/网络卷时自动降至低并发档（避免寻道抖动互相拖累） |
| 读缓冲 | `sync.Pool` 复用 | — | 1 MiB 流式缓冲 / 128 KiB 小文件一趟缓冲 / 64 KiB 采样缓冲 / 16 MiB 段缓冲各自成池，杜绝分配风暴 |
| 清理操作并发 | 4 | 4 | 单文件元数据 syscall 延迟主导，有界并发缩短大批量耗时 |

### 3.6 paranoid 模式（逐字节确认）

开启后，每个重复组内的所有文件与代表文件做**逐字节流式比对**（256 KiB 双缓冲，整趟只分配一对）。任何不一致者移出组并计入失败清单。适用于内容正确性要求极高的场景（如备份核对），代价是结果阶段多一趟全量读盘。

## 4. 哈希缓存：存放位置与复用策略

缓存模块：`internal/cache/cache.go`（SQLite + WAL）。缓存的唯一目的是**加速二次及以后的扫描**——首次扫描全量计算，之后未变化的文件直接复用上次的哈希，跳过全量读盘。缓存丢失只影响速度，不影响结果正确性。

### 4.1 存放位置

缓存与设置都存放在系统配置目录下的 `FileDedup/` 文件夹（`os.UserConfigDir()`）：

| 平台 | 路径 |
|---|---|
| macOS | `~/Library/Application Support/FileDedup/` |
| Windows | `%AppData%\FileDedup\` |
| Linux | `~/.config/FileDedup/` |

目录内容：

| 文件 | 说明 |
|---|---|
| `cache.db` | SQLite 哈希缓存主库 |
| `cache.db-wal` / `cache.db-shm` | WAL 模式伴随文件 |
| `settings.json` | 应用设置（线程数、主题、语言、默认过滤器） |

配置目录不可用时的回退：退到家目录 `~/.filededup/`。

### 4.2 数据结构

```sql
-- 主表：每行 = 一个文件的哈希记录
CREATE TABLE hash_cache (
    path     TEXT    NOT NULL PRIMARY KEY,  -- 文件绝对路径
    size     INTEGER NOT NULL,              -- 文件大小（字节）
    mtime_ns INTEGER NOT NULL,              -- 修改时间（纳秒）
    partial  BLOB    NOT NULL,              -- 32 字节：4 采样点 xxHash64（小文件=全文件哈希）
    full     BLOB,                          -- 32 字节 BLAKE3-256；NULL = 未算过全量
    last_hit INTEGER NOT NULL DEFAULT 0,    -- 最近命中时间（LRU 依据）
    dev      INTEGER NOT NULL DEFAULT 0,    -- 物理身份：设备号（unix；Windows 为 0=未解析）
    ino      INTEGER NOT NULL DEFAULT 0,    -- 物理身份：inode
    ctime_ns INTEGER NOT NULL DEFAULT 0     -- 物理身份：状态变更时间
);
-- 索引
CREATE INDEX idx_cache_last_hit ON hash_cache(last_hit);
-- 元信息表
CREATE TABLE cache_meta (key TEXT PRIMARY KEY, value TEXT);  -- 记录算法语义版本
```

注意：**大文件预筛淘汰后只缓存采样（partial），full 为 NULL**——它从未被全量读过，自然没有全量哈希可存。

### 4.3 命中判定（复用条件）

一次扫描中，某文件的缓存行被复用必须**同时满足四道检查**：

1. **元数据一致**：`path` 存在，且当前 `size` 与 `mtime_ns` 与缓存行完全一致；
2. **物理身份一致**：当前文件的 `(dev, ino, ctime_ns)` 与缓存行记录一致（unix；身份未解析的 Windows 卷跳过此道）。路径同、时间戳同但已被换成另一个 inode（覆盖写、COW 恢复、换盘）会被这一道拦下；
3. **采样一致**：即使前两道一致，应用仍会重读 4 点采样（≤256 KiB）并与缓存中的采样指纹比对——防止 `cp -p`、COW、FAT 2 秒粒度、原地改写保 mtime 等情况造成"内容变了但时间戳没变"的假命中；
4. **采样非全零**：采样为全零的行视为脏行（历史版本缺陷遗留），一律不信任、重算。

四道全过才信任缓存中的 `full`，**免除阶段 3 的全量读盘**；任何一道不过即当作未命中重新计算。采样比对的开销极小（每文件最多 256 KiB），换取的是"缓存绝不造成错误分组"的强保证。

### 4.4 写回策略

- **批量 UPSERT、单事务**：整个任务（含取消的任务）结束时一次性写回所有新算哈希，避免逐条提交的 IO 放大。取消的任务不浪费——已算出的哈希照常入缓存。
- **原位补全**：大文件阶段 2 先写采样行，阶段 3 算完全量后**原位更新**该行的 full 字段（而非追加新行），避免覆盖把采样清零。
- **命中续期（LRU 语义）**：命中的文件在任务结束时批量刷新 `last_hit`，保证高频访问的热文件不被淘汰。
- **写入防御**：UPSERT 时若新采样为全零则保留旧采样。

### 4.5 版本控制与失效

缓存行内含算法语义版本（当前 `blake3-256+xxh64-4pt+id-v3`）。以下任一变化都会 bump 版本：哈希算法或长度、采样点数与采样参数、字段语义、表结构（v3 新增 dev/ino/ctime_ns 身份列）。**版本不符（含旧库无版本标记）时整表作废重建**——防止旧语义的缓存行继续命中、造出错误分组。

### 4.6 容量与淘汰

- 条目上限：**500,000** 条。
- 超限时按 `last_hit` **最旧优先淘汰**（配合命中续期，即标准 LRU）。

### 4.7 损坏自愈与维护

- 打开失败（库损坏）时**自动删除重建**，最坏退化为一次首扫速度。
- 缓存不可用不阻塞应用：只在启动时于 stderr 留痕一次，本次运行全量重算。
- 手动清空：设置里的"清空缓存"（`CacheClear`）只清哈希表，不动元信息。
- 体积参考：macOS 正常运行时主库约 16 KB 起，随文件数增长（每条约 100+ 字节）。

### 4.8 CLI 场景的缓存复用

`fdd-cli` 默认禁用缓存；传 `-cache <db路径>` 启用。可让 GUI 与 CLI 共用同一个 db，或给 CLI 单独指定一个长期缓存路径，实现跨次运行复用。

## 5. 扫描过滤器详解

过滤器在扫描前一次性**预编译**（扩展名集合小写归一；≥12 项时建哈希 map 查表，短列表走线性比较），逐文件判定零热路径开销。

### 5.1 可用过滤条件

| 条件 | 语义 |
|---|---|
| 包含扩展名 | 空 = 全部；如 `.jpg`（大小写不敏感） |
| 排除扩展名 | 命中即跳过 |
| 最小/最大大小 | 0 = 不限 |
| 包含隐藏文件 | 默认排除 `.` 开头的文件与目录 |
| 排除路径（glob） | 见下 |

### 5.2 排除路径 glob 语义

| 模式形态 | 匹配范围 |
|---|---|
| `node_modules`、`*.tmp`（不含 `/`） | 任意路径段（目录名或文件名）命中即排除 |
| `a/b`、`a/b/`（字面前缀，无通配） | 该目录及其**全部后代** |
| `a/b/**`（末尾递归） | 同上，跨任意层 |
| `a/b/*`（末尾单 `*`） | 仅 `a/b` 的**直接子层**，不含更深后代 |
| `*/build`、`a/**/b` 等（通配在中间） | 精确按模式匹配相对路径，不向后代传播 |

### 5.3 目录级剪枝

为让"排除"真正省时间，满足以下条件之一时，命中的**目录**会被整棵剪掉（不再进入遍历）：

- 模式不含 `/`（如 `node_modules`）；
- 模式是字面前缀式（`a/b`）或末尾递归式（`a/b/**`）。

其余形态（通配在中间、末尾单 `*`）只做文件级判定——因为按它们剪枝可能误删本该保留的深层文件，结果正确性优先。

## 6. 结果阅读与清理操作

### 6.1 重复组

每组列出：组内文件（路径、大小、修改时间）、单文件大小、**可释放空间 = (文件数 − 1) × 单文件大小**。结果默认按可释放空间降序，其次按组号；也可按文件大小 / 文件数排序，或按扩展名筛选。分页默认 100 组/页，上限 500。

### 6.2 保留策略（一键决策）

| 策略 | 规则 |
|---|---|
| 路径最短（默认建议） | 保留路径最短者；同为路径最短时**不在隐藏目录**中的优先 |
| 保留最新 | mtime 最大者 |
| 保留最旧 | mtime 最小者 |
| 保留指定目录 | 支持添加**多个目录并排序**（↑/↓ 调整优先级，越靠上优先级越高）。组内保留「命中的最高优先级目录」下的那份；同一目录命中多份时保留路径最深者；组内无任何匹配时该组保持现状 |
| 手动 | 按前端已有勾选 |

**保护生效时机**：执行"应用保留策略"落定决策后，任何清理操作都不会作用于保留文件（后端硬拦截，逐个报「保留文件不可操作」）。未应用策略的组仅在界面上把"路径最短（同级优先非隐藏目录）"者标为**保留建议**——建议标记不是保护，此时勾选它照样会被清理，请先应用策略再执行操作。

### 6.3 四种清理操作

| 操作 | 行为 | 安全机制 |
|---|---|---|
| 移入回收站（推荐默认） | macOS 经 Finder（osascript：路径走 argv 无转义面，每 100 个一批、单批 2 分钟超时防 Finder 无响应挂死）；Windows 系统回收站 API；Linux **自研 XDG Trash**（零外部依赖，不依赖 `gio`；写规范 trashinfo，重名按 `.2/.3` 递增且设有界上限） | 批量失败自动退化为逐文件执行并隔离错误项；可随时取消；Windows 上网络/不可回收卷**直接拒绝**（此类卷的"回收站删除"实为静默永久删除） |
| 永久删除 | `os.Remove` 直接删除，**不可恢复** | 后端强制要求显式确认标志，无确认拒绝执行 |
| 移动 | 移到指定目录，重名自动递增（`name_1.ext`） | 目标目录必须是本会话内经目录选择器**显式授权**的路径（后端校验，拒绝任意路径）；**串行执行**——并发移动同目录同名文件会产生覆盖竞态，安全优先于速度 |
| 硬链接合并 | 用保留源与重复文件合并为同一物理文件，释放目录项占用 | 保留源与目标各自校验内容与物理身份（inode），防"校验后被替换"反向覆盖 |

### 6.4 操作前内容校验（核心安全机制）

每个待操作文件在执行前都会重新校验（`internal/ops/verify.go`）：

1. 文件已消失（ENOENT）→ 记为**跳过**（目标已达成），不计失败；
2. 打开后**立即 fstat**，当前大小与扫描时不一致 → **拦截**（文件已非扫描时那份）；
3. 其余情况**在同一个已打开的文件句柄上重算全量 BLAKE3** 与组哈希比对：一致才放行（例如仅 touch/chmod 过），不一致一律拦截——哈希所依据的就是随后被操作的那份打开内容，消除"校验与删除之间文件被替换"（TOCTOU）窗口；
4. 真正执行删除/移动/合并前，再确认路径上的 `(dev, ino, ctime_ns)` 仍是校验时那份文件；已被替换则**拦截**（Windows 身份不可解析的卷上此道退化为恒通过，安全由第 3 道的句柄绑定兜住）。

> 特别说明：这里**不做"时间戳没变就放行"的捷径**——实测同一时钟刻度内的原地改写可以让 mtime/ctime 逐纳秒不变（FAT32/exFAT 甚至 2 秒内都不变），时间戳无法证明内容未变。代价是大批量清理时多一趟读盘，换取"绝不误删被改过的文件"。

### 6.5 操作结果四态

| 状态 | 含义 |
|---|---|
| OK | 执行成功，计入释放空间 |
| Skipped | 执行时文件已不存在（视为目标已达成） |
| Failed | 校验拦截或系统错误，逐项注明阶段与原因 |
| Cancelled | 取消后未派发的条目，不会从结果集中移除 |

成功/跳过的文件会从结果集中移除，组内不足 2 个时整组消失。

### 6.6 扫描历史

每次**成功完成**的扫描会自动保存一条结果快照到「记录 → 扫描历史」（`history.db`，与哈希缓存 `cache.db` 分离，上限 20 条，超出淘汰最旧）：

- **恢复**：把历史结果重新载入为当前结果集，可直接继续清理——即使相关应用会话早已结束。载入不遍历磁盘，陈旧文件安全由操作前逐文件校验兜底（§6.4）：已被修改的拦截、已消失的按跳过处理。结果页顶部会显示「当前为历史结果」横幅。
- **重扫**：按该条历史的配置（目录/过滤器/线程数/paranoid）重新发起扫描，过滤器数值自动换算回界面 KB 口径。
- **联动裁剪**：在恢复的历史结果上继续清理后，该历史行的文件数与可释放空间同步更新（原始快照数保留展示为「已清理 n」），下次恢复看到的是修剪后的存量。
- 保留决策（含「保留指定目录」结果）随历史持久化，恢复后建议标记不丢。
- 删除/清空历史只影响账本，不影响磁盘文件与当前结果集。

### 6.7 清理记录与回撤

每个清理操作在**动手之前**先把完整计划写入账本（写前日志，`history.db`），执行中逐条收口实际去向。由此：

- 应用若在执行中崩溃/被强杀，重启后残留「待处理」条目会收口为**中断**徽标，提示去文件系统核对现状；
- 「记录 → 清理记录」列表展示每次操作的时间、类型、条数、已回撤数与回收空间，点「明细」可逐文件查看状态与失败原因。

**可回撤范围**：

| 操作 | 应用内回撤 | 说明 |
|---|---|---|
| 移入回收站 | macOS / Linux 支持 | 从回收站落点搬回原路径；Windows 回收站 API 拿不到可靠落点映射，记录标注「不可回撤」，请用「打开系统回收站」手动还原 |
| 移动 | 支持 | 从新位置搬回原目录（重名自动递增，不覆盖） |
| 硬链接合并 | 支持 | 拆除链接、恢复独立文件，并从保留源重建内容 |
| 永久删除 | **不支持** | 文件已不在磁盘上，无从恢复 |

**回撤的安全规则**（与正向操作同等严格）：

1. 只处理「已执行」条目；已回撤/失败/跳过的项不重复动。回撤失败的项会留痕原因，修正后可再次回撤（天然幂等）。
2. 回收站/移动回撤前提：落点文件仍在且大小与记录一致；**原位置已被占用时不覆盖**，改以 `名称.fdd-restored.扩展名` 落地。
3. 硬链接回撤三重防线：目标必须仍是指向保留源的那个 inode（被换成别的文件即拦截）；从保留源复制出的内容必须全量 BLAKE3 等于扫描时组哈希（源被篡改即拦截）；全部通过才原子替换，失败时目标现状分毫不动。
4. 回撤不冲销执行账本（「已执行」计数保留），也不自动改动结果集——恢复完成后建议**重新扫描**刷新。
5. 「清空记录」会连带丢弃回撤能力，二次确认时会明确警示。

## 7. 界面功能说明

| 功能 | 说明 |
|---|---|
| 暂停 / 恢复 | 停止派发新工作、在途最小单元完成后挂起：目录遍历按**目录边界**停、预筛/哈希按**文件边界**停、paranoid 比对按**组边界**停；恢复回到原阶段继续 |
| 取消 | 全部 worker 尽快退出：遍历在取目录前中断（不再对剩余目录读盘）、哈希/比对在**每个文件与每 256 KiB 块**处检查（大文件也能秒级停下）；已算哈希照常写缓存，不浪费。取消中断的文件**不计入失败清单** |
| 内部故障 | worker panic 被拦截并转为**失败（Failed）**状态上报（错误信息含故障阶段），不再伪装成"已取消"，也不再有单个 panic 拖垮整任务或进程 |
| 进度 | 文件数 + 字节数双口径、速度与 ETA；分阶段总量自动切换（预筛读量 / 全量读量），不虚满 |
| 结果预览 | 图片 → 512px JPEG 缩略图（源 ≤20MB、解码 ≤16M 像素防炸）；文本 → 前 4KB；二进制 → 前 256B HEX |
| 定位 | 系统文件管理器中打开并选中该文件 |
| 记录页 | 两个标签：**扫描历史**（恢复/重扫/删除，§6.6）与**清理记录**（明细/回撤/打开系统回收站/清空，§6.7） |
| 设置 | 线程数（0=自动，1–64，与引擎同一口径钳制）、主题 light/dark/system、语言 |

## 8. 命令行工具 fdd-cli

冒烟/批量场景使用，输出 JSON 报告：

```bash
fdd-cli [选项] 目录...

  -threads N        worker 数（0 = 默认 核数-1）
  -paranoid         逐字节确认
  -min-size N       最小文件大小（字节）
  -max-size N       最大文件大小（0 = 不限）
  -exclude LIST     排除扩展名，逗号分隔，如 .tmp,.log
  -hidden           包含隐藏文件
  -o FILE           输出到文件（默认 stdout）
  -cache PATH       哈希缓存 db 路径（空 = 禁用缓存）
```

报告含统计（文件总数 / 失败数 / 组数 / 可释放字节 / 重复文件数）、全部分组与失败清单。

## 9. 使用建议与最佳实践

**操作安全**

1. 首选**回收站**而非永久删除；确认无误后再清空回收站。
2. 重要数据扫描时开启 **paranoid** 模式，用多一趟读盘换零风险。
3. 执行前浏览一遍结果；结果页的"保留建议"是路径最短（优先非隐藏目录）者，不一定符合你的意图，逐组确认或用"保留指定目录"策略。
4. **硬链接合并的前提**：与保留源在同一文件系统（跨设备会失败）；合并后修改任何一个路径的内容会影响所有路径——只对"纯占用、永不再单独修改"的副本使用。

**扫描效率**

5. 善用排除路径剪枝 `node_modules`、`.git`、`build`——目录级剪枝能整棵跳过，比逐文件过滤快得多。
6. 用包含扩展名/大小下限缩小候选（如只查 `.mp4`、≥100MB），预筛阶段读盘量按比例下降。
7. **第二次扫描才体现缓存价值**：同根目录反复扫描时，未变化文件直接复用哈希，通常只重算变更部分。缓存命中依旧会重读 4 点采样做安全比对，所以不会为了速度牺牲正确性。
8. 机械盘/网络卷不用手动调参，自动并发已按介质降档；SSD/NVMe 保持默认（核数 − 1）即可。

**缓存维护**

9. 大规模增删文件后（如迁移目录树、路径批量改名），路径是缓存主键——旧路径条目会随 LRU 自然淘汰；想立即回收空间可在设置里清空缓存。
10. 缓存文件损坏无需处理：应用下次启动自动重建。
11. 疑似误报时优先怀疑缓存以外的问题（如文件正在被写入）；缓存侧已有四道命中检查兜底，正常使用无需手动清理。

## 10. 常见问题 FAQ

**Q：为什么 0 字节文件和符号链接不出现？**
内置跳过，防止空文件假组与链接环路，不可关闭。

**Q：两个文件内容一样但大小不同，为什么没判为重复？**
按内容判定要求大小也一致（这是分桶第一层）。大小不同说明内容必然不同——多半是行尾/编码/元数据差异，FileDedup 不做"近似重复"判定。

**Q：文件被我修改过但 mtime 没变，会不会被误删？**
不会。操作前会重算全量哈希比对内容（§6.4），时间戳不参与放行判断；扫描阶段缓存命中也要求采样指纹一致（§4.3）。

**Q：扫描很慢，第二次会快吗？**
会。缓存命中可跳过全量哈希；只有新增/修改过的文件需要重算。首次扫描全量计算属预期。

**Q：缓存放在哪？能删除吗？**
见 §4.1。可以安全删除，应用会自动重建，仅损失二次扫描加速。

**Q：硬链接的多个路径为什么只显示一个？**
同一物理文件只计一次（阶段 1.5），否则"可释放空间"会是虚数。想为它们节省空间时用"硬链接合并"处理的是**内容相同的不同文件**。

**Q：移动操作为什么比其他操作慢？**
移动是唯一串行执行的操作——并发移动会产生目标重名覆盖竞态（静默数据丢失），安全优先于速度。

**Q：取消扫描后刚才算的哈希白算了吗？**
没有。取消路径同样会批量写回缓存（§4.4），下次扫描直接复用。

**Q：回撤成功后，为什么结果页还显示那些文件？**
回撤只动磁盘文件，不反改当前结果集（结果集是扫描时的快照，回撤恢复也可能是另名落地）。看到「回撤完成」提示后重新扫描一次即可刷新。

**Q：为什么有的清理记录标着「不可回撤」？**
两种：永久删除（文件已不在磁盘，无从恢复）；Windows 的回收站操作（系统 API 不返回可靠落点，只能到系统回收站里手动「还原」，界面上有「打开系统回收站」按钮）。

**Q：历史恢复出来的结果安全吗？**
安全。载入历史不碰磁盘，之后每个清理动作仍走 §6.4 的操作前全量内容校验——文件在扫描后被修改过会被拦截、已消失的按跳过处理，不会误操作。
