## 二、P2-1 图标语言统一

### 2.1 问题

审查原文：*"侧栏用文字符号 `◎ ⧉ ⚙`，操作按钮用彩色 emoji `👁 📂`，标签用 `★ ✕ ↷ 🎉`"*。

问题不只是"风格不一致"。实测下来是**三套互不兼容的渲染机制并存**：

| 来源 | 字形 | 机制 | 后果 |
|---|---|---|---|
| A 文字/几何符号 | `◎ ⧉ ⚙ ▾ ▸` | 普通字体字形 | 字号、基线、光学重量随字体变化；粗细与正文一致，做图标偏细 |
| B 单色 dingbat | `★ ✕ ✓ ↷` | 符号字体 | 同样受字体度量影响；不同平台字形差异明显 |
| C 彩色 emoji | `👁 📂 🎉` | 彩色字体 | **带固有颜色，`color` 属性完全无效**；同一排按钮里 `👁` 是彩色而旁边的 `✕` 跟着文字变色 |

C 类是最硬的伤：emoji 无法响应 hover / active / 主题切换。实测确认——修复前把宿主按钮的 `color` 改成任意值，`👁` 的颜色纹丝不动。

### 2.2 方案

新增统一线性图标集（内联 SVG，24 网格，`stroke="currentColor"`，几何取自 Lucide / MIT）：

- `frontend/src/components/icons.ts` — 图标几何数据 + `IconName` 类型 + 语义映射表 `KIND_ICONS`
- `frontend/src/components/Icon.vue` — 渲染组件，`<Icon name="eye" :size="15" />`

**为什么几何数据要放在独立的 `.ts` 而不是 `Icon.vue` 的 `<script setup>` 里**：`<script setup>` 不允许 ES 模块导出，把类型放在那里只能依赖编译器的宽容行为；而且图标名是跨组件公共契约（导航、按钮、角标都要引用），放在纯 TS 模块里才能被 `tsc` 正常检查。图标恒为纯装饰，带 `aria-hidden="true"`，需要名称的按钮把名称放在按钮自身的 `aria-label` 上。

**`currentColor` 的三重证明**（不是推断，是实测）：

1. **静态**：1597 个图标，`getComputedStyle(svg).stroke` 与其自身 `getComputedStyle(svg).color` 逐一比对，0 个不一致。
2. **动态（改宿主颜色）**：给 `.op` 按钮设 `color: rgb(1,2,3)`，图标 `stroke` 立刻变成 `rgb(1,2,3)`；清掉后恢复原值。
3. **动态（真实 hover）**：用浏览器真实指针事件悬停 `.op` → 宿主 `color` 变 `--primary`，图标 `stroke` 同步跟到 `rgb(37,99,235)`；移出鼠标后一起复原。

图标按语义自动取色（实测值，亮色主题）：

```
scan / gear（未激活导航）   → rgb(74, 84, 100)   = --text-2
layers（激活导航）          → rgb(37, 99, 235)   = --primary-ink
star（保留）                → rgb(6, 95, 70)     = --success-ink
close（冗余）               → rgb(185, 28, 28)   = --danger-ink
eye / folder-open           → rgb(100, 108, 121) = --text-3
```

### 2.5 本轮附带发现并修复的缺陷

统一图标的过程暴露了一个**此前一直存在、但被"文字恰好撑开了盒子"掩盖掉的真实缺陷**：

#### ① `.tag` 类名与全局样式表冲突 → SVG 视口被压到 2px

- **现象**：toast 角标的图标渲染成 1 个像素点，而不是叉/感叹号/勾。
- **定位**：`getScreenCTM().a = 0.0833`，而 18px 盒子 / 24 网格应为 `0.75`。`0.0833 = 2 / 24`，说明 SVG 的**内容盒只有 2px 宽**。
- **根因**：`style.css:192` 有一条**全局、无作用域**的 `.tag` 规则（给 GroupCard「图片组」徽章用），带 `padding: 1px 8px`。`ToastHost.vue` 的角标也叫 `.tag`，全局 padding 与组件里的 `width/height: 18px` + 全局 `box-sizing: border-box` 叠加：`18 − 8×2 = 2px`，于是 SVG 按 2px 视口做了 `preserveAspectRatio` 等比缩放。
- **为什么以前没被发现**：角标原来是文字 `<span>`，全局 padding 只是把它撑成了 16px 宽的胶囊，看起来"还行"；换成 SVG 后同一份 padding 直接吃掉了视口。
- **修复**：角标类名改为 `.toast-tag`，与全局徽章解耦。同时补齐 warn / info 两种角标的语义配色（原先只有 error / success 有，warn / info 落在中性灰上）。
- **验证**：`getScreenCTM().a` **0.0833 → 0.75**，`padding` `1px 8px → 0px`，四类角标各自取到 `--danger-ink` / `--warn-ink` / `--primary-ink` / `--success-ink`，对底对比度 5.54 / 4.51 / 4.37 / 6.88 : 1。

#### ② 表单控件缺可访问名（P2-3 延伸）

审查第六节只点了"纯符号按钮无名称"，本轮全量扫描可聚焦元素时发现同类问题比预期多——**而且是量级问题**：

| 位置 | 问题 | 数量 |
|---|---|---|
| `GroupCard.vue` 文件行复选框 | `<label>` 只包住 input，旁边的「保留/冗余」是兄弟节点，未被关联 → 复选框没有可访问名 | **约 500 个 / 页** |
| `ScanView.vue` 粘贴路径输入框 | 只有 `placeholder`（占位符不能当标签，聚焦即消失） | 1 |
| `ResultView.vue` 排序下拉 / 保留策略下拉 / 保留目录输入框 / 目录选择按钮 | 用 `<span class="lbl">` 当视觉标签，不是 `<label>`；「…」按钮的文字就是「…」 | 4 |
| `SettingsView.vue` 主题 / 语言 / 默认线程数 | `.row label` 是裸 `<label>`（既未包裹控件也无 `for`），与控件没有关联 | 3 |

全部补上 `aria-label`（复选框的名称带上文件名，即「标记为删除 xxx.png」/「保留项 xxx.png（不可勾选）」）；`ResultView` 里那个视觉用的 `<span class="lbl">` 加 `aria-hidden="true"` 避免与控件的 `aria-label` 重复播报。

**验证**：三页可见可聚焦元素 1510 / 12 / 9 个，无名控件 **0 个**（修复前结果页仅"1 个禁用的复选框"是假象——那是在空态页面上量的）。

## 五、P2-7 预览面板信息补全（重点项）

审查原文：*"不显示文件类型/大小/修改时间；Markdown 源码原样展示（`# 世界观设定 v12`）；无「在文件夹中打开」"*。

修复前的面板只有两样东西：一行路径、一个关闭按钮。用户打开预览后仍然不知道这是什么类型、多大、什么时候改的，也没法回到磁盘定位；而文本内容直接 `<pre>` 铺开，Markdown 的 `#` / `**` 全带着，等于把面板退化成 `cat`。

证据截图（`docs/ui-review-2026-09-16/`）：修复前 `09-preview-text.png`；修复后 `32-after-p27-preview-rendered.png`（亮色渲染态）、`33-after-p27-preview-source.png`（亮色源码态）、`34-after-p27-preview-dark.png`（暗色渲染态）、`35-after-p27-preview-overcap.png`（超限默认源码）。

### 5.1 三处改动

| 子项 | 修复前 | 修复后 |
|---|---|---|
| 元信息 | 无 | 标题行下新增元信息行：完整路径（mono，可 hover 看全文）+ 三枚 chip「`MD · Markdown`」「`122.4 MB`」「`2026/8/10 18:00:00`」 |
| 定位磁盘 | 无 | 「在文件夹中打开」按钮，复用结果行同一个后端能力 `RevealInFolder` |
| Markdown | 源码原样 | 默认**渲染**呈现（标题/段落/列表/引用/代码块/分隔线），可一键切回源码逐字核对 |
| 标题 | 只有路径 | 文件名为主标题（长路径不再把文件名挤掉），路径移到元信息行 |

类型标签由 `FileView` 已有的 `path/name/size/mtime` 推导，**未新增任何后端字段**——元信息在渲染层已经拿得到，让 Go 侧重跑一次 `stat` 只是重复劳动。

### 5.2 为什么自己写解析器，而不是引 `marked` + `v-html`

预览内容来自**用户磁盘上的任意文件**，是不可信输入。用 `v-html` 渲染 Markdown 就必须自己保证净化正确，一旦漏一个 `<img onerror>` 就是任意脚本执行。

这里改成：`parseMarkdown()` 把文本解析成**结构化数据**（`Block[]` / `Seg[]`），交给 Vue 模板用插值渲染。Vue 的插值天然转义，**从根上没有 XSS 面**——不需要"净化"，因为不存在把字符串当 HTML 执行的路径。唯一会把外部字符串写进属性的地方是链接 `href`，用协议白名单 `safeHref()` 挡掉 `javascript:` / `data:` / `vbscript:`，被拒的链接退化成纯文本而不是可点链接。

副作用是零依赖（项目只有 `vue` + `pinia`），没有为一次预览引入一个新包。

**注入实测**（构造恶意 Markdown 后打开预览）：

| 断言 | 结果 |
|---|---|
| `window.__x1/__x2/__x3`（脚本 / `onerror` / `javascript:` 各自试图设置的全局） | **全部 `undefined`** |
| 面板内 `<script>` / `<img>` / `<iframe>` / `<svg>` 节点数 | **0 / 0 / 0 / 0** |
| 面板内带 `on*` 内联事件属性的节点数 | **0** |
| `href` 以 `javascript:` 或 `data:` 开头的链接 | **0** |
| 实际渲染出的链接 | 仅 `https://example.com`、`./a.md`（`javascript:` 那条退化为纯文本） |
| `<script>…</script>` 的显示形态 | 以**字面文本**出现在 `<h1>` 内 → 转义成立 |

解析覆盖率（同一份恶意样本）同时验证：`h1`×1、`p`×3、`blockquote`×1、`ul li`×2、`ol li`×2、`hr`×1、`pre`×1、围栏内 code×1、行内 code×1、`strong`×1、`em`×1、`del`×1 —— 各类块级/行内语法都正确落到对应元素。

### 5.3 顺带发现并修复：组件复用会残留上一份文本

`MdInline` 原本在 `setup` 里一次性执行 `parseInline(props.text)`。而 `MarkdownView` 用**下标**做 `v-for` 的 key，连续预览两份 Markdown 时子组件实例会被复用（只更新 props），一次性求值的结果就停留在上一份文本上。

实测：连续预览 `INDEX.md` 与 `INDEX (1).md`，两步的 `<h1>` 分别是 `文件 1701`、`文件 1702` —— 改为 `computed` 后不再残留。（该项在第一次测量中并未暴露：两次内容恰好相同，是专门构造"按 id 生成不同内容"的桩才复现出来的。）

### 5.4 顺带发现并修复：大文件同步解析会冻住界面

渲染器是同步的，面板也不做虚拟滚动，代价随文档线性增长。用 rAF 采样帧间隔实测：

| 文档 | 渲染 DOM 节点 | 主线程阻塞 |
|---|---|---|
| 20 KB | 2 091 | 36 ms |
| 100 KB | 10 440 | 141 ms |
| 400 KB | 41 724 | **450 ms** |

400 KB 量级已是一次肉眼可见的卡顿，且 4 万节点会长期驻留内存——**这是本次改动新引入的风险**，不修等于用一个功能换一个性能坑。

处理：设 `MD_RENDER_MAX = 64 KiB`，超限文件**默认退回源码**（源码只是一个 `<pre>`，代价恒定），元信息行加一枚琥珀色「默认源码」chip、按钮带 tooltip 说明原因，**但保留手动渲染入口**——把选择权交给用户，而不是替他把界面冻住半秒。

实测（100 KB 文档）：

- 打开时按钮为「渲染预览」（即当前是源码态），`title` = `正文 100.0 KB，超出 64.0 KB 渲染上限，已默认显示源码；仍可手动渲染`，chip 出现「默认源码」，面板内无 `.md` 节点、有 `<pre>`；
- 手动点「渲染预览」后 → 13 740 个节点正常渲染 ← 用户选择未被剥夺；
- 常规 `< 64 KB` 文件仍默认渲染，无 chip、无 tooltip。

### 5.5 交互与无障碍复验（面板从 1 个按钮变成 3 个）

| 断言 | 结果 |
|---|---|
| 「在文件夹中打开」真的调用后端 | 探针包裹 `RevealInFolder` → 点击后收到 `[1701]`，与目标文件 `INDEX.md` 一致 |
| 打开后焦点进入浮层 | ✓（落在首个可聚焦元素「查看源码」） |
| Tab ×5 是否逃逸 | 5 次全部 `inside = true`，顺序 `查看源码 → 在文件夹中打开 → 关闭 → 查看源码 → 在文件夹中打开` |
| Esc 关闭后焦点归还 | ✓ `restoredToTrigger = true`（回到触发它的「预览」按钮） |

`role="dialog"` / `aria-modal="true"` / 可访问名「文件预览」均保持。

### 5.6 对比度回归

新增的元信息行 / chip / 渲染视图一并纳入扫描（面板是 `<main>` 的兄弟节点，原扫描选择器覆盖不到，已扩到 `.panel.box *`）：

| 场景 | 参与判定元素 | 失败 | 最差 |
|---|---|---|---|
| 亮色 · 渲染态 | 2 422 | **0** | 4.83:1（`.badge`，11px） |
| 暗色 · 渲染态 | 2 422 | **0** | 4.79:1（`.label`，11px） |
| 亮色 · 源码态 + 超限 chip | 13 662 | **0** | 4.83:1 |
| 暗色 · 源码态 + 超限 chip | 13 662 | **0** | 4.79:1 |

「默认源码」chip 的文字色一开始用了 `--warn-ink`，实测它在 `--warn-weak` 叠加 `--bg-hover` 后的实际底色上只有约 4.1:1（亮）/ 4.2:1（暗），够不到正文 AA，已改为 `--text`（保留琥珀底色作为注意信号）。

## 六、P2-2 字号阶梯与 P2-8 状态去重

### 6.1 P2-2：字号阶梯

修复前全站出现 **10 个不同字号**（9 / 10 / 10.5 / 11 / 11.5 / 12 / 12.5 / 13 / 14 / 15px），其中 9px 与 10px 落在可读内容上，11.5px 与 12.5px 是只此一处的孤立取值。字号档位一多，"次级信息"在不同页面就会落到不同档，无法保持一致性。

按审查第七节的建议收敛为 5 档并绑定语义角色（`style.css`）：

```
--fs-xs   11px  仅角标/徽章（导航未读徽章、图片组标记、保留/冗余标签、统计格小标题）
--fs-sm   12px  次级文字（路径、时间、提示、表单标签、统计条文字、提示条正文）
--fs-base 13px  正文、按钮、列表主文本（body 默认值）
--fs-lg   15px  面板/浮层标题、统计数值、空态标题、品牌字
--fs-xl   20px  页面标题（当前 UI 尚无此角色，预留）
```

**实测（含新预览面板）**：UI 控件层恰好 **4 档** —— `11px ×507`、`12px ×1004`、`13px ×907`、`15px ×5`。

渲染出的 Markdown **文档内容**另用 `13px`（正文）/ `15px`（h2）/ `20px`（h1）表达层级，用到的正是上面预留的 `--fs-xl`。文档内容不是 UI 骨架：标题需要层级，把 h1 压到面板标题同尺寸反而是错的。因此判定口径分开：**UI 层 4 档不变，文档内容按需取用预留档位。**

顺带修掉一处对比度：9px 导航徽章提到 11px 后实测 4.83:1；而全站扫描暴露出唯一一处失败——激活导航标签「`--primary-ink` 文字 + `--primary-weak` 底」只有 **4.37:1**（差一点点到 4.5）。把 `--primary-ink` 由 `#2563eb` 压深到 `#1d4ed8`：对 `--primary-weak` **5.66:1**、对面板白 **6.70:1**。修后全站 2 411 个元素 × 2 主题 **0 失败**。

### 6.2 P2-8：状态重复表达

**① 运行态标题两个近义状态**：原来同一行同时出现「全量哈希」与「哈希中」。
处理：运行态只保留阶段名（阶段本身已隐含"进行中"），暂停态仍保留「已暂停」——因为"暂停"不是任何阶段的隐含态，必须显式说出。

**② 398 个红胶囊**：组卡片每行同时用「勾选框 + 红色 `✕ 冗余` 胶囊」表达同一概念，137 组下整页被红色淹没。而"冗余"其实是**缺省状态**（每组只有 1 个保留项），把缺省态标成警示色本末倒置。
处理：保留项 = 绿底胶囊（唯一的"决策"，需要跳出来）；冗余项 = 无底色 + `--text-3` 的弱标记。两者图标同尺寸、文字同为 2 个汉字、padding 相同，宽度一致（约 53px），文件名列不会因标记类型不同而左右跳动。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 危险色文本节点 | **400** | **2** |
| 标记胶囊宽度 | 不一致 | 统一 **53px** |
| 文件名列位置 | 随标记类型漂移 | 稳定 **x = 200** |
